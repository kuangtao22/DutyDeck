# 运维工作台（Server Ops）

> 一句话定位：把服务器、数据库和 Redis 的日常维护收进 DutyDeck 同一个工作台——能看、能查、能连，危险动作默认停在你手上；同时允许 Agent 在你显式授权的只读范围内帮你排障。

## 它解决什么问题

个人开发者做产品时，最频繁「离开产品」的动作大多发生在服务器这一侧：登服务器看负载、翻日志定位报错、查表结构确认字段、跑一条 SQL 对数据、传一个文件、看一眼容器状态。这些事单件都不大，但它们分散在终端、数据库客户端、日志面板、文件传输工具和云控制台里，每次切换都要重新拼一遍上下文；凭据也常常散落在各处。

运维工作台把这类维护工作归到一个地方，并且因为 Agent 就在同一个客户端里，可以让「我刚看到的东西」变成「它也能安全读到的东西」——前提是你显式授权，且范围、期限都写在界面上。

## 能做什么

**按项目组织**

- 抽屉一级是项目，进入项目后分成服务器 / 数据库 / Redis 三个分组；连接归属固定为创建时所在的记录，支持在项目之间移动连接。
- 项目只是选择入口，不参与权限继承（把连接移进某个项目不会自动获得任何 Agent 权限）。

**SSH 服务器**

- 连接管理：地址、端口、用户名，认证方式支持密码、私钥文件（含可选 passphrase）与 SSH Agent。
- Host Key 指纹：首次连接停在确认态，展示算法与 SHA-256 指纹；已固定指纹发生变化时直接阻断，不提供「仍然连接」。
- 概览：真实的系统、资源、磁盘、网络与高占用进程数据。
- 远程终端：可交互的真实 PTY，支持输入、resize 与输出流。
- 服务（systemd）：搜索、筛选与检查服务；启动、停止、重启、修改开机自启动需要在明确确认后执行。
- 日志：读取系统或指定服务的历史日志，可进入实时跟随。
- 远程文件：通过 SFTP 有界分页浏览目录，支持预览、编辑、另存、上传、重命名与删除；写入沿用主进程签发的短时候选与内容校验。
- 文件传输：传输任务与进度集中在传输面板中。
- Docker：容器 / 镜像面板与容器控制台。

**数据库与 Redis**

- 支持 MySQL、PostgreSQL、Redis 连接，以及直接拖入本地 SQLite 文件。
- 库 / 表清单与结构浏览：列、索引、可空、默认值、注释等。
- 数据浏览：按主键排序分页读取，支持行过滤与单元格查看。
- SQL 工作台：编辑器带补全与语法校验，执行结果与查询历史可回看。
- 数据库诊断：按引擎提供只读诊断视图（如连接、版本、运行状态）。
- Redis：连接与只读诊断。键浏览暂未提供。

**让 Agent 参与（只读授权）**

- 在连接详情与聊天输入区顶部可以开启「Agent 只读授权」，按会话授予具体资源范围：SSH 概览（日志正文单独授权）、MySQL / PostgreSQL / SQLite 的库表范围（结构 → 行数据 → SQL 查询三层能力）、Redis。
- 授权状态在界面上始终可见，例如「运维只读 · 某项目 / 某库 · 结构 · 剩余 24 分钟」，由主进程授权事件驱动，不轮询数据库。
- 没有授权时，Agent 工具返回结构化状态和固定的下一步；界面只提供「管理运维授权」入口，不会自动授予权限，也不会把未授权的连接目录泄漏给模型。

## 典型使用流程

1. 打开运维工作台，新建或选择一个项目。
2. 添加服务器：选择认证方式并填写公开字段；密码与私钥口令由主进程加密保存，界面**不会回填明文**，只显示「凭据已保存」，可随时替换或清除。
3. 首次连接确认 Host Key 指纹；之后点击「连接」直接使用已保存凭据，凭据缺失或认证失败时才弹出补录窗口。
4. 日常排障按「概览 → 服务 → 日志 → 终端」的顺序走；需要看文件用远程文件 / 传输面板。
5. 数据库排障按「连接 → 库表结构 → 数据 / SQL → 查询历史」走。
6. 需要 Agent 帮忙时，在连接详情顶部开「Agent 只读授权」，选好库表与能力范围，再到普通 Agent 会话里提问；到期或撤销后 Agent 立即失去读取能力。

## 安全与边界

- **凭据**：密码、私钥内容与口令只以 Electron `safeStorage` 密文形式存放在 `credentials.json`（数据源凭据单独一份）。公开 DTO、日志、审计、Toasts、错误消息与 Renderer 状态里都不含明文；在 `safeStorage` 不可用或降级为明文后端时，记住凭据的操作 fail closed，不会退化成明文存储。
- **默认只读**：面向用户的读取默认只读；写入、删除、重启、`sudo` 等操作要么只生成脚本，要么逐次请求确认，且不提供「始终允许」。
- **Agent 授权**：授权绑定真实会话（`sessionId`）与连接身份，只保存在主进程内存中，固定 30 分钟到期且不因调用自动延期；最多 8 个会话同时有效，每个会话最多 32 个资源。扩权、缩权、重新保存或到期后重新授权都会产生新的 revision，并立即取消该会话旧 revision 的排队与在途请求。
- **失效条件**：显式撤销、到期、会话归档 / 删除、连接删除、连接身份或凭据变化、应用退出都会让授权失效；这些由主进程事件处理，不依赖当前打开的页面。
- **不继承**：项目归属不继承权限；自动化、委派子会话、画布内部运行与外部触发都不继承会话授权。
- **运维只读模式**：该模式下的 Agent 只注册白名单内的 `ops_*` 只读工具，不注册 Shell、文件读写、浏览器、任意 MCP 与委派工具，宿主分派层同样拒绝白名单外的调用。切换到该模式会重建工具集，不复用普通编码运行时的实例。
- **审计**：`audit.json` 保留最近 5000 条记录，命令文本进入公开审计时截断到 512 字符，错误只公开稳定的错误码，不写入凭据与秘密。
- **必须知道的边界**：撤权只能阻止后续读取，已经交给模型的历史内容收不回来；行数据会发送给你选择的模型，敏感列遮罩不等于完整匿名化；普通编码 Agent 仍可使用 Shell 等其它能力访问资源，运维只读工具的白名单不约束它们。

## 数据存在哪里

所有配置都在 `~/.proma/server-ops/` 下，使用原子写入，并由跨进程配置锁保护协作写者：

- `hosts.json`：服务器公开字段（名称、地址、端口、用户名、认证方式、`credentialRef`、标签与时间戳）。
- `credentials.json`：SSH 凭据的版本化 `safeStorage` 密文。
- `known-hosts.json`：Host Key 算法与 SHA-256 指纹、确认时间（不含秘密）。
- `data-sources.json` / `data-source-credentials.json`：数据库与 Redis 连接及其凭据密文。
- `projects.json`：项目与连接归属。
- `query-history.json`、`schema-cache.json`：SQL 查询历史与表结构缓存。
- `database-agent-policy.json`：数据库侧的 Agent 授权策略。
- `audit.json`：运维操作审计。

## 与其他模块的关系

- **与 Agent**：存在两套边界清晰的授权——面向服务器的 `server_*` 操作工具使用「当前会话 + 当前服务器」的显式临时授权，写操作逐次审批；面向多资源的只读能力走独立的 `ops_*` 只读授权通道。两者互斥：授予旧操作授权会撤销所有只读授权，反之亦然，提交前会显示将被撤销的会话数量。
- **与画布 / 接口工作台**：没有直接耦合。它们各自独立，只是共同使用同一份本地优先配置与审批习惯。

## 已知限制

- Redis 目前提供连接与只读诊断，未提供键浏览。
- 只读授权中的 SSH 概览需要服务器处于已连接状态。
- 只读授权与旧 SSH 操作授权全局互斥，服务器写操作仍会打断会话级只读访问（这是当前有意的兼容选择）。
- 队列与并发是有限资源：每个数据源串行执行，全局最多 3 个并发读取，超出时排队并在等待超时后给出明确状态，不会自动重跑已开始的 SQL。
