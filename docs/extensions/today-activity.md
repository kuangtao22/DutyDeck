# 今日活动（Today）

> 一句话定位：给同时推进多个项目的个人开发者一份「今天的流水账」——不管在哪个项目、走的是 Chat 还是 Agent，今天动过的会话按最后一次对话时间排成一条时间线，点一下就能回去接着做。

## 它解决什么问题

个人开发者的一天很少只在一个项目里：主产品的会话开着，突然要去查线上问题、联调一个接口、回一个 issue、顺手问一个临时问题。这些活动散落在不同项目、不同模式（Chat / Agent）、不同会话里。

到了晚上想回顾「今天到底推进了什么」，或者第二天想回到昨天没做完的那条线上，只能靠记忆去猜在哪个项目里翻——项目的会话列表按项目分组，记忆恰好是最不可靠的那一环。

今日活动把这件事变简单：它不改变会话的归属，只是把**当天发生过对话的会话**跨项目汇总成一条按时间排序的列表。你不需要回忆「当时是在哪个项目里问的」。

## 能做什么

- **跨项目单列表**：不再按项目分组，当天所有会话按最后一次对话时间（`updatedAt`）降序排成一条流水。
- **Chat 与 Agent 各自成表**：侧栏当前是哪种模式，今日活动就展示该模式的当日条目。
- **包含委派子会话与定时任务会话**：它们是真实发生的会话活动，同样出现在列表里；Agent 模式下委派子会话以缩进 + 左侧竖线呈现，与活跃列表保持一致的层级感。
- **排除不该出现的东西**：已归档会话（归档有独立入口）、尚未发送首条消息的草稿会话、以及内部执行会话都不会出现在这里。
- **保留原有行内操作**：切换会话、重命名、置顶 / 收藏、归档、删除等操作与活跃列表一致（Agent 会话还支持移动），不需要为了「回看」再切回去。
- **入口常驻且带计数**：侧栏底部的「今日活动 (N)」常驻显示，N 为当前模式的当日条目数；为 0 时不显示计数。
- **跨零点自动重算**：判定「今天」用的是本地时区自然日，列表随相对时间刷新重算，不会出现过了零点还挂着昨天的流水。
- **空态直说**：当天没有会话时显示「今天还没有会话（对话）」，不伪造内容。

## 判定规则（「今天」是怎么算出来的）

- **时间口径**：按本地时区当天 `00:00:00.000` 为起点，`updatedAt >= 今日零点` 的未归档会话才进入列表。
- **只做内存计算**：筛选与排序是纯函数，不读磁盘、不发 IPC，数据仍来自界面已加载的会话元数据；因此它很轻，也不会因为打开这个视图产生额外 I/O。
- **排序**：统一按最后一次对话时间降序，Agent 侧复用侧栏既有的会话排序函数，保证与其它入口的排除规则一致。

## 典型使用流程

1. 打开侧栏，在底部点「今日活动」。
2. 列表按最后一次对话时间倒序展示今天的所有会话；点任意条目直接进入该会话，继续原来的上下文。
3. 需要回到项目分组时，点底部的「返回活跃会话 / 返回活跃对话」。
4. 切换 Chat / Agent 模式，今日活动按当前模式重新计算。

## 安全与边界

- 今日活动只做**展示与跳转**，不新增网络请求、不新增加密能力，也不搬运会话内容——列表里只有标题、工作区、时间这类元数据。
- 它不会把归档会话重新拉回可见范围；归档与今日活动是两个互不干扰的入口。
- 会话本身仍然按原有方式落盘，今日活动不产生新的数据副本。

## 数据存在哪里

- Agent 会话索引：`~/.proma/agent-sessions.json`（轻量元数据）。
- Agent 会话消息：`~/.proma/agent-sessions/{id}.jsonl`（JSONL，逐行追加）。
- Chat 对话与会话元数据同样位于 `~/.proma/` 下的配置与 JSON / JSONL 文件，未引入本地数据库。

## 与其他模块的关系

- 今日活动是「当天视角」的统一入口，与画布、运维工作台、接口工作台没有直接耦合：在这三块里做的工作只要产生了会话，同样会出现在今日活动里。
- 与 Agent 协作能力配合最明显：委派子会话算作当天活动，所以一条被拆给子 Agent 的长任务，晚上回看时能在同一条流水里看到主会话和它的子会话。

## 已知限制

- 只提供「今天」，没有「本周 / 自定义日期区间」的视图。
- 统计范围是当前已加载的活跃会话元数据；已归档会话不计入，也不提供「包含归档」的开关。
- 内部执行会话不出现在列表里，这是有意为之（它们不是给人看的会话）。
