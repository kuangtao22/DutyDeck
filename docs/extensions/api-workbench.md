# 接口工作台（API Workbench）

> 一句话定位：把接口当成可维护的资产，而不是一次性粘贴的请求——集合、环境、变量、鉴权、加密方案和用例都沉淀在项目里；手动操作与 Agent 共用同一条执行链路，每个结论都能打开真实运行记录核对。

## 它解决什么问题

做产品的日常里，接口联调是最碎的活之一：换个环境就要改一遍地址；鉴权方式散在各个工具和文档里；同一个接口的测试规则写在聊天记录里，过几天就找不回来；接口报错只有一句「401」，想看看到底发了什么请求头、耗时花在哪一段，还得再找工具。

接口工作台把这类工作收拢到一处，并且把「配置」和「证据」分开：**集合**保存可复用的配置，**运行记录**保存真实执行证据。你和 Agent 用的是同一个执行服务，所以 Agent 说「这个接口是 401」时，你可以直接打开它引用的那条记录自己核对。

## 能做什么

**组织与归属**

- 接口资产归属当前 workspace，内部按「集合 → 文件夹 → 请求」组织；请求不随聊天会话删除，历史记录里保留发起会话的可失效引用。
- 环境（本地 / 测试 / 生产等）属于同一 workspace，可供多个集合显式选用；不自动继承运维连接、模型渠道或浏览器登录态。
- 一个工作区标签内可以有多个请求编辑标签，显示方法、名称、未保存标记与执行状态；新建请求可以先发送，再决定保存到哪个集合。

**请求能力**

- 协议：HTTP / HTTPS，HTTP/1.1 是首个明确支持的传输版本；支持 JSON、普通正文与 SSE 响应。
- 方法：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。
- URL 与参数：原始 URL、路径变量、查询参数、启用 / 禁用行、重复键与编码预览。
- 请求头：有序键值行、重复字段、启用开关、描述，并显示每项的来源（继承 / 自动添加 / 用户填写）。
- Body：none、JSON、文本 / XML、urlencoded、multipart 表单（含文件）与二进制文件。
- 鉴权：无鉴权、Bearer、Basic、API Key（Header 或 Query），支持集合级继承与单请求覆盖。
- Cookie：独立的按 workspace / 环境分区的临时 Cookie Jar，可查看收发明细、清空与禁用；不共享浏览器 Cookie。
- 发送选项：超时、是否跟随重定向、最大跳数、直连或显式 HTTP 代理，连接复用状态可见。
- 测试：无脚本断言——状态码、Header、JSON 字段存在 / 类型 / 值、耗时，输出期望值与实际值。
- 导入导出：cURL 常用参数导入（只解析参数，**绝不执行 shell**）、cURL 导出、自有集合格式导入导出；导出默认用占位符替换秘密。

**变量与公共配置**

- 四层作用域：工作区级、集合级、环境级、接口级；接口级只存「用哪套方案」与覆盖项，不存值。
- 取值顺序固定为「接口覆盖 → 运行时变量 → 环境 → 集合 → 工作区」，界面能显示某个值最终来自哪一层，避免「改了不生效」。
- 秘密变量单独存放并加密，界面上只显示「已配置」；未解析的变量会在发送前报出字段位置。
- 公共配置统一管理变量与密钥、签名与加密方案、公共请求头 / 参数 / 鉴权：算法与模板是工作区级约定，改一处全体一致，可审计、可 diff。

**加密与签名**

- 接口只负责「选方案」，具体步骤写在公共配置里；目录里每条请求显示所用方案，一眼看出哪些接口有加密。
- 算法集：摘要 / 签名 MD5、SHA1、SHA256、HMAC-SHA1、HMAC-SHA256、SM3；对称 AES-128-CBC、AES-256-CBC、AES-128-GCM、SM4-CBC；非对称 RSA-OAEP、RSA-PKCS1v15、SM2（具体支持按实现收敛）。
- 密钥与 IV 只引用变量名（`keyRef` / `ivRef`），永远不内联到方案里。
- 步骤按数组顺序执行，顺序就是语义：签名在加密前是签明文，在加密后是签密文。
- 缺密钥或密钥未填写不会阻塞发送：该步骤跳过，本次运行被标记为「明文发出」，状态条如实显示形态（例如「已解密 · AES-128-CBC」「未解密 · 本地缺少 aesIv」）。
- 收到响应后按 `responseSteps` 解密 / 验签，再交给断言与提取；解密失败默认停止（fail closed）。

**运行记录（调试证据）**

- 每次发送产生独立的运行记录：运行身份、编辑时的请求模板、**最终请求**（解析后的方法与 URL、实际发送的 Header 与 Body 字节）、响应概览、响应头、正文（原始字节与解码结果分开）、Cookie 明细、分阶段耗时、重定向每一跳、连接与 TLS 信息、SSE 事件、断言结果与故障分类。
- 每项观测值都带 `captured / derived / unavailable` 状态：只有真实采集到的才标「实际」，推导值写明口径，不可观测的写原因，不伪造 `0 ms`，也不把连接错误伪装成 HTTP 500。
- 摘要默认便于浏览，细节按页签展开；大正文可以分页读取、复制或另存为示例。
- 4xx / 5xx 仍然是「收到了一次响应」的运行：网络结果、HTTP 状态、测试结果分别显示；没有断言时显示「未验证」，不会因为 200 就宣称业务通过。

**场景（多步流程）**

- 可以把多个已保存请求按顺序编排成场景；一次审批覆盖整条流程，审批卡上列出每一步的方法与 URL。
- 执行严格按声明顺序进行，某步失败会停止后续（除非场景设置 `onFailure=continue`），每一步仍保留自己的运行记录。
- 前面步骤提取的变量可以通过 `{{name}}` 传给后续步骤。

**与 Agent 协同**

Agent 侧提供 15 个窄工具：`api_list`、`api_get_request`、`api_prepare_request`、`api_send_request`、`api_inspect_run`、`api_save_request`、`api_prepare_scenario`、`api_run_scenario`、`api_save_scenario`、`api_save_environment`、`api_update_requests`、`api_extract_base_url`、`api_declare_variables`、`api_save_crypto_profile`、`api_bind_crypto_profile`。

- **发送与保存是两次独立审批**：网络审批不等于保存授权，保存也不会重新发送。
- 重复调用 `api_send_request` 会复用同一次运行，**绝不重发**；需要重试时必须显式准备新的身份。
- `api_prepare_request` 返回固定脱敏预览，密钥始终留在宿主侧；提取到的响应值直接进入宿主侧运行时变量，不回传给模型。
- 批量整理（改名、移动文件夹 / 集合、绑定环境）走 `api_update_requests`，一次审批最多 50 条，审批卡逐条列出「从什么改成什么」；它绝不修改 URL 与正文。
- 把硬编码主机抽成 `{{baseUrl}}` 走 `api_extract_base_url`，由宿主挑选与改写，不交给模型拼 URL。

## 典型使用流程

1. 新建请求：手工填写，或粘贴 cURL 导入（只解析参数）。
2. 选择环境，确认变量解析来源，发送；界面同时产生一条运行记录。
3. 打开运行详情定位问题：状态码、最终请求头、耗时分段、重定向跳转、TLS 与 Cookie 明细。
4. 修改草稿后显式复测，得到新的运行记录，旧记录保持原样，便于对比。
5. 把稳定下来的配置写回集合：断言、环境变量、公共配置；需要批量整理就让 Agent 用 `api_update_requests` 分批处理。
6. 想让 Agent 接手时，直接说清目标，例如：「用测试环境检查用户详情接口，说明为什么 401，修好请求配置后复测并保存。」

## 安全与边界

- **秘密**：秘密变量与密钥加密保存、不回显；审批卡只列出变量名。`api_declare_variables` 只能声明名称，**永远不能写值**，需要人到公共配置面板填写；同名变量已存在时保持不动，不会被覆盖。
- **人工用例受保护**：Agent 新增的用例会被标记为 agent 来源并要求人工复核；人创建的用例不能被 Agent 修改或删除，越界请求会在审批之前直接拒绝（`API_WORKBENCH_USER_CASE_PROTECTED`）。
- **文件上传**：只允许 multipart 中明确列出的文件；宿主解析 `realpath` 与大小，把每个路径展示在审批卡上，人工批准后才读取字节。目录、设备、FIFO、断开符号链接与超过 20 MiB 的文件会被拒绝；准备之后被改动过的文件也会拒绝上传。已保存的请求只保留文件引用，新会话需要重新声明路径。
- **不可信内容**：接口响应与页面内容一律当作不可信数据，不能当作指令执行。
- **取消语义**：点击取消只证明客户端停止，不证明服务端已回滚请求。
- **不做任意脚本**：不提供 Postman 式 Pre-request Script；需要非标算法时走受限的步骤与模板合同，而不是允许脚本读凭据、出网或写盘。

## 数据存在哪里

- 根目录：`~/.proma/api-workbench/`，按工作区分目录保存集合目录（`catalog.json`）、环境与变量、签名加密方案、场景、运行记录与响应示例等，全部为本地 JSON 文件，使用原子写入。
- 变量中的秘密值通过主进程加密后保存，界面只回传「已配置」状态。
- 上传文件的真实路径只存在于主进程内存：不落盘、不出主进程；落盘的只有文件名、大小与类型这类元数据。

## 与其他模块的关系

- **与运维工作台**：没有直接耦合。接口测试环境不会自动继承运维连接、模型渠道或浏览器登录态；需要复用地址时请在环境变量里显式声明。
- **与 Agent**：手动与 Agent 共用同一执行服务与同一份运行记录，所以 Agent 给出的每个结论都能被打开核对；这也是这个模块能被信任的前提。

## 已知限制

- 传输能力以 HTTP/1.1 为主，SSE 已在范围内，其余协议能力仍在推进。
- GCM 的 tag 位置属于后续阶段，当前 GCM 步骤会被跳过而不是猜测实现。
- 请求的正文与参数目前只能逐条准备和保存；批量工具只处理改名、分组、集合与环境绑定，不碰 URL 与正文。
- 变量替换遵循各自的编码规则，不做无类型的全文替换，避免破坏 JSON 或造成双重 URL 编码。
