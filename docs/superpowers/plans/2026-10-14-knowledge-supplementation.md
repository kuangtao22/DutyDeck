# 知识库补充与整理流程实施计划

## 目标

让知识库从“首次建库”扩展为可持续维护流程，覆盖旧库导入、项目分析、当前会话补充、目录整理和索引冲突恢复，同时保留正文、附件、链接、来源与版本证据。

## 实施步骤

1. 修复知识读取证据登记：凡正式读取流程中实际可读且有正文的 JSON、源码和文档来源，都能进入本轮发布证据；元数据、不可读、失效或引用不一致的来源继续拒绝。
2. 修复索引发布基线：以最近一次发布的索引摘要校验写入，避免系统扩展计划时误判人工编辑；保留真实人工修改保护，并提供只读预览、版本校验、备份后显式重建入口。
3. 增加旧知识库安全导入暂存：宿主选择文件或目录后，在项目受管暂存区保留正文、附件、相对路径和链接；重复导入幂等，源变更形成新版本，拒绝路径逃逸、符号链接、凭据和超限文件。
4. 接通维护服务、运行时、IPC、preload 和 renderer：补充菜单提供导入、项目分析、当前会话补充、整理目录及单篇补充；所有任务沿用 Pi Agent、来源读取和现有知识写入合同。
5. 扩展默认 knowledge-maintenance Skill，明确四类入口、保留正文的导入规则、会话证据边界、目录整理和失败恢复动作，并递增 patch 版本。
6. 用 BDD 回归覆盖正常路径、重复导入、边界拒绝、索引冲突恢复和 JSON/源码发布，再运行相关测试、类型检查、构建或可执行的 UI 冒烟检查。

## 兼容与性能约束

- 不新增模型服务或数据库，知识与协作记忆继续独立。
- 普通补充保持目录稳定；只有用户明确整理时才移动、合并或拆分，并保留来源与重定向信息。
- 导入使用有界扫描、异步限读和原子暂存，避免大文件或目录扫描阻塞 Electron 主进程。
- 所有 JSON/session/manifest 写入使用现有原子文件工具，失败可恢复且不覆盖人工内容。
