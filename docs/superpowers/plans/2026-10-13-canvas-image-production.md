# Canvas 图片生产链路优化实施计划

## 目标

把画布中的“空制作卡、统一媒体结果、正式图片卡、候选和采用版本”收敛成可追溯的单卡生产链：配置、运行、候选和采用版本都绑定同一交付目标；连线继续表达真实输入关系；旧画布提供可预览、可恢复的整理操作。

## 已批准的行为合同

1. 模型选择 ID 在目录、保存、读回和执行之间使用同一解析合同；供应商身份必须和 profile 一致。
2. 同一交付目标使用一张图片卡。生成前冻结目标配置和真实请求，完成后回填原卡并进入既有 Job/candidate/adoption 链。重复回执幂等，迟到结果只保留为候选，不覆盖新配置或已采用素材。
3. 空卡允许提前连线规划，折叠卡显示“等待上游素材”。正式运行结果绑定生成时的输入版本，保留现有 `derives` 执行语义。
4. 待配置、运行、失败、候选和已采用状态由同一张卡投影；Agent 复用原卡，不重复创建平行成品卡。
5. 旧画布按任务、运行和素材证据提供可预览、可恢复的归并操作，保留素材、历史、所有边和布局；不按标题盲合并，不改在途节点。

## 实施顺序

- 共享层：补充有限图片准备摘要和 `image-preparation` 变化事件，严格解析并保持旧快照兼容。
- 主进程：LOAD 一次性提供摘要；配置保存、回填和恢复广播专用事件；接入回填服务、原子 receipt 和既有候选事务。
- Agent 工具：增加“准备回填/回填结果”窄工具，要求先冻结 attachment，再执行或等待统一媒体完成；回填不自动采用。
- Renderer：按单卡投影运行、失败、候选、采用和等待上游素材状态；同 revision 的准备事件刷新摘要，恢复期间合并刷新。
- 旧数据：提供基于明确任务/运行/素材证据的预览、应用和恢复接口，复用现有删除/恢复事务。
- 指导与验证：更新默认 Canvas production skill，补充重复空卡和回填规则；运行定向 BDD、共享类型检查、Renderer 构建和 Electron 类型检查。

## 验证证据

- 模型合同相关回归：已通过 146 项定向测试。
- 原卡回填服务及统一媒体来源读取：已通过 186 项定向测试。
- Renderer 单卡状态、等待上游素材和同 revision 刷新：已通过 278 项测试，隔离构建通过。
- 待完成：共享快照/事件合同、主进程生产 DI、工具接线、旧卡整理 API，以及最终 Electron 类型检查和相关 Canvas 全套测试。
