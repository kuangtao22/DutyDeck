# 项目知识库 Implementation Plan

> 后续修订（2026-10-08）：本计划保留首版实施与验证记录。后续重构以[自有目录与主题提炼方案](../specs/2026-10-07-project-knowledge-simplified-extraction.md)为准：动态目录与索引由 Agent 编排、项目记忆统一正文、接口文档由工作台呈现。下文“memory 原位作为独立正文”等旧边界不代表新方案；重构尚未实施，不能用已有完成项代替其验收。

> **For agentic workers:** 使用 `subagent-driven-development` 的分工、测试与独立评审方式逐项实施；保持现有未提交改动。用户已要求开始，完成一个节点后继续推进后续节点。

**Goal:** 在现有项目记忆入口交付可扫描、可检索、可持续沉淀和整理的项目知识库，让新会话按需取得项目依据。

**Architecture:** 主进程知识服务拥有扫描、条目版本、索引、维护队列和写门禁；原文件和 memory 正文保持原位。共享 IPC 连接统一知识视图，普通前台标准 Agent 由宿主注入有界检索结果。跨进程锁与 manifest 原子发布保护归属和并发，读取不自动扫描。

**Tech Stack:** Bun、TypeScript、Electron IPC、React/Jotai、JSON/Markdown、现有 safe-file 与文件锁；不新增依赖。

## 范围与不变量

- 设计依据：`docs/superpowers/specs/2026-10-07-project-knowledge-base-design.md`，已合入本次评审修正。
- 阶段：1A 资料检索 → 1B 对话沉淀 → 1C 受管整理；PDF/Office/OCR 和外部刷新保留第二阶段边界。
- 原文件原位保存；`.proma/**` 不进入通用扫描；现有 memory 编辑器继续可用。
- 项目根从已登记工作区解析；同根不同 ID 不得覆盖归属；未知/非法 ID、路径穿越、软链接、来源撤权均 fail closed。
- UI、Agent 与后台不能绕过主进程的版本、来源与权限判断；现有 Automation、Collaboration、external 和受限运维不扩权。
- 工作区已有未提交的运维与显式记忆实现属于本次起点，禁止回退、混入提交或重写。
