# 编排工厂优化闭环实施计划

**目标：** 将独立评测并入运行，让当前 DutyDeck Agent 提出候选草案，用户在采纳前用同一批保存任务比较当前版与草案。

**架构：** 复用 JSON/JSONL 场景、草案与运行存储，扩展现有 runScene 四层契约。候选运行不改生效版本；运行记录保存候选身份与定义快照。对比不另建 Agent 会话、不直接修改用户项目。

**技术：** Bun、TypeScript、React、现有 Radix 组件；不新增依赖。

## 实施与验收

- [x] 后端：先覆盖未采纳草案整链运行、缺失/过期草案、过期基线与标准变化的拒绝测试，再补 shared、runner、IPC、Agent 工具与接线。运行结果明确区分当前版和草案，试跑不推进版本、不污染任务。
- [x] 运行入口：主导航收敛为场景/运行/交付；批量评测放到运行内部，继续保留数据集与历史。当前运行与历史保留原布局。
- [x] 优化对比：已有任务按需加载，默认选最近一条，可多选；按钮明确将执行两版。固定初始版本和草案身份，顺序执行以限制并发开销；错误停止后续任务，完成结果保留。对比展示改动、判据证据、输出和耗时，不制造综合分数。输入、标准、实际模型或占位状态不可比时明确原因。
- [x] 采纳：比较后展示已测试草案是否仍为当前草案；沿用人工采纳，过期候选不得用旧结论背书新草案。
- [x] Agent Skill：补读取报告→核对失败原因→准备草案→相同任务/标准对比→人工采纳；评审失败不能用于业务提示词优化，标准修改独立处理。递增默认 Skill patch 版本。
- [x] 验证：运行 factory 相关 Bun 测试及 Electron typecheck；浏览器隔离预览验证导航、多任务比较、查看原文、历史恢复及窄面板；单任务执行由 IPC 参数集成回归覆盖。记录真实模型调用未执行的边界。

## 兼容与开销

旧记录缺少候选元数据时仍能查看，但不能伪造可比结论。批量对比每条任务执行两次流程及各自评审，按需发起、顺序执行；不增加轮询频率。用户现有草案、数据集、运行记录与其他模块改动保留。

## 验证结果

- 前端与默认 Skill：147 项通过；后端、IPC、Agent 接线合同、共享类型及参考 runner：182 项通过，合计 329 项，无失败。
- Electron 与 shared 类型检查通过；主进程、Agent runtime、preload 在临时输出目录完成 bundle 检查，不覆盖 dev 产物。构建保留既有 dev-bundle-freshness 的 CJS/import.meta 警告。
- 浏览器内存预览：两条合成任务分别保留基线与候选输出，查看逐项证据与左右详情，切页后恢复两组对比，人工采纳生成 v3；390×560 视口无横向溢出，检查后恢复默认视口。
- 未调用真实模型或访问应用数据库，未验证真实 Agent 的多轮遵循效果；预览里的改善是模拟结果，不代表业务提示词实际提升。候选采纳后仍需按新生效版本完成交付验证。
