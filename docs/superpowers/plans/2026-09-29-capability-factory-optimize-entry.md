# 基于本轮优化：实施与验收

目标：按用户已确认方案，从自动评审结果将优化请求追加到当前 DutyDeck 会话，补足运行与版本迭代之间的入口。

设计：复用项目 Button、结果详情及当前 Agent 编辑器。沿用按 sessionId 定向事件和同步应答的交互；编辑器追加纯文本事务，保留已有富文本引用、正文和撤销能力，不修改现有新会话预填语义，不自动发送、不调用模型、不新建会话。

- [x] 添加请求生成与可用性测试：锁定场景/运行/版本，评审失败、未完成、占位数据与无效输出不得作为内容优化依据。
- [x] 添加编辑器事务与事件回归：保留选中正文及引用，HTML 作为字面量；会话隔离、重复挂载只应答一次、卸载后失败。
- [x] 结果页添加「基于本轮优化」与成功/失败反馈，运行页显式传入当前会话上下文；独立对比详情不新增跨弹窗操作。
- [x] 为 Agent 编辑器增加末尾追加接口，共用原有同步及持久化链路。对模型评审建议只引用记录，避免将建议或原始正文直接当作新指令拼入草稿。
- [x] 使用隔离预览的真实 RichTextInput 验证按钮点击、原草稿保留、追加及一次撤销；预览不装载 Agent、不调用模型。
- [x] 运行相关 Bun 测试与 Electron typecheck，检查差异格式；记录真实模型和当前用户客户端未做端到端发送验证的边界。

影响：仅新增一次点击的本地文本构造及编辑器事务；不改变执行器、版本采纳、其他面板业务或网络调用。保留当前工作区其他未提交改动，不增加依赖。

验收：相关 156 项测试通过，Electron 类型检查通过。浏览器实测原草稿“我已有的补充要求，请保留。”追加后仍存在，撤销回到原文。未向用户真实会话发送消息或执行真实提示词优化。
