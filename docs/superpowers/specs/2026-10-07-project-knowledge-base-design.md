# DutyDeck 项目知识库设计

日期：2026-10-07

后续修订（2026-10-08）：当前产品方向以[自有目录与主题提炼方案](2026-10-07-project-knowledge-simplified-extraction.md)为准：Agent 根据项目与用户要求动态编排真实目录及索引，项目记忆统一到库内正文，接口文档归接口工作台。以下保留首版实现背景；与新方向冲突的固定分类、独立记忆正文和接口文档归档方式不再作为后续实施依据。该重构仍处方案阶段。

状态：用户于 2026-10-07 在规划评审后要求开始，按修订后的三阶段方案实施；完成状态以实施计划及测试证据为准。

最新决策（2026-10-07）：知识提炼直接复用当前项目 Agent 与 `knowledge-maintenance` Skill，取消独立维护开关、渠道、模型及日预算。旧后台调度方案已退役，历史作业仅作兼容记录，不能继续发起模型请求。

## 1. 目标与成功标准

每个项目拥有可长期维护的知识库，覆盖项目规划、业务、市场调研、使用说明、规则、技术与接口文档、交互与视觉稿、图片资产，以及决策和协作记忆。

新项目通过扫描获得可用的知识基础；日常对话产生的明确决策、纠正和已核验事实能够增量沉淀；新会话按任务取得必要上下文，并能沿引用回到原始依据。目录和文件随着知识增长持续整理。

“保持最新”的可验证含义是：对已纳入范围、可观察的来源变化及时失效相关摘要，并显示核验时间、处理状态和冲突。不能保证未访问的外部网页、未观察到的部署状态或待处理对话已经同步。

## 2. 已有基础与需要补齐的能力

- `WorkspaceMemoryTab.tsx` 已有“建立项目地图与协作画像”入口，记录维护授权并创建引导会话；不是自动执行完整项目扫描的后台服务。
- `workspaceMemoryInitPrompt.ts` 与默认 `knowledge-maintenance` Skill 已约定项目地图、协作记忆、长文档和会话临时资料的分工，并要求按主题整理。当前主要依赖 Agent 遵循提示词。
- `proma_memory_record` 已提供当前工作区的 Markdown 追加、原子保存和完全重复重试去重；尚无结构化知识来源关联、语义去重或冲突合并合同。
- `agent-memory-refresh-service.ts` 处理历史证据邀请；当前 Agent 提炼仅处理当前用户声明和登记来源，不把历史补充提示当作读取全部旧会话的授权。
- Vault 已有 Markdown 编辑、双链与保存冲突处理，但配置是全局资料根。复用组件和编辑能力，项目知识库使用独立项目身份。
- Canvas/Design 的文档、原型和图片，API 工作台的接口定义，继续由各自服务保存。旧 Design 创作资料库入口仅在 legacy 工作区可达，不作为新知识库的主入口。
- 现有项目文本索引在搜索时同步递归刷新，并只检查文件首段；不能直接承担新知识库的交互式全文搜索。

## 3. 知识分类与事实来源

2026-10-07 用户实测纠正：知识库的默认内容必须由系统提炼产生。扫描文件清单属于来源层，不能因文件可读就标记“已确认知识”，也不能把“已读取文本”当作“已提炼”。此约束优先于首版把两层混在“资料”页中的实现。

默认页面为“知识”，另设“来源资料”和既有“记忆文件”。来源层保留原文件、版本与本地检索索引；知识层保存按主题综合后的简明事实、约束和决策，并附可核验的原文引用。对话开始默认查询知识层，Agent 可以通过明确的来源范围继续核对原文。

“更新知识库”先完成来源扫描，再将显式 Skill 任务提交到同项目 Agent 的现有消息队列。使用会话已有模型；忙碌时排在当前任务之后，输入草稿保留。普通对话也可按需处理新增或变更来源。代码、测试和构建产物不逐个送去总结。文件提炼默认保留为草稿；同一结论的来源版本更新不能被正文去重吞掉，用户拒绝的固定证据不能仅因模型改写措辞而复活。

初期每回合最多处理四个来源，单页最多读取 24 KiB，并共享 Agent 全回合累计读取预算。超出部分明确标示未完整分析，不能承诺全文已覆盖。原来源仍保留分页读取入口。PDF/Office 正文和图片识别继续沿用第二阶段边界。

界面默认提供：项目总览、规划与市场、产品与业务、技术与接口、设计与资产、规范与指南、决策与记忆。分类可调整，不为凑分类创建空文档。

业务分类与文件形式分离。市场调研可以来自 Markdown、PDF 或网页引用；交互设计可以来自图片、HTML 或 Canvas 节点。普通文件可登记和预览，尚未提取正文的格式明确显示只能检索元数据。

每项知识有稳定身份，并分别记录：

- 内容类型：资料、项目事实、业务推断、决策、经验、协作偏好、规则。
- 内容状态：草稿、已确认、已替代、已归档。
- 新鲜度：与来源版本一致、来源已变化待复核、来源不可用、尚未核验。
- 来源：项目文件与内容摘要、文档章节、会话消息身份、Canvas 节点及 revision、接口身份及 revision，或外部链接与采集时间。
- 适用范围、确认依据、发生或生效时间，以及引用和替代关系。

内容状态与新鲜度互相独立。已经确认的历史决策可以仍然成立，但它引用的资料可能需要复核。文件修改时间只参与变更检测，不能替代业务生效时间。

用户直接表达的偏好和明确作出的决定可以作为相应类型的依据；用户转述的部署结果仍是转述。Agent 的建议、总结或“已完成”声明不单独构成项目事实。代码现状与应遵守的规范也分别记录。

## 4. 项目身份与存储

统一目录以现有 `AgentWorkspace.id` 为项目身份。服务端通过真实工作区索引解析 slug 和文件根；适配历史会话字段时显式解析，不能仅因字段名同为 workspaceId 就假定表示相同身份。

首版每个真实项目文件根仅允许一个知识库所有者。首次初始化在跨进程锁内记录工作区 ID；同根的其他工作区、软链接别名以及复制项目后不同工作区 ID 的访问均返回明确归属冲突，不改写既有清单。该限制只针对知识库接入，不改动现有工作区创建行为。原工作区迁移目录仍保留 ID；复制为独立项目须显式导入并重建本地绑定，不能继承原维护授权。

知识库管理的项目文档与关系元数据拟放在 `<项目文件根>/.proma/knowledge/`，正文采用 Markdown，元数据与日志采用 JSON/JSONL。无本地代码目录的项目继续使用现有托管 `workspace-files` 文件根。

现有来源保持原位：

- 项目中的 `docs/`、`.context/` 等文件登记引用，不因接入知识库而整体移动。
- 工作区 `memory/` 仍保存协作记忆；知识目录关联主题与条目，不复制一套记忆正文。
- Canvas/Design、接口工作台通过各自服务提供受控引用；不直接遍历其内部目录或复制资产成为第二份权威内容。
- 两层 `AGENTS.md` 保留既有所有权和作用域，只维护紧凑入口及已生效约定；不会被扩展成知识全文集合。

检索索引放在活动数据根下的项目缓存目录，可由正式资料重建。维护设置、队列、处理检查点与来源排除记录随项目 manifest 原子发布，不能当作可任意丢弃的缓存。显式记忆操作日志放在既有 memory 目录，不进入知识文件扫描。

资料写入、分类变化和引用更新由项目写队列串行提交，并核对读取基线。涉及多个文件时需要可恢复的提交记录，以原子切换清单版本作为发布边界；仅对每个文件分别调用原子写，不能声称整个变更已经具备事务性。

权威入口固定为 `manifest.json`，包含 `schemaVersion`、`projectId`、递增 `revision`、条目头版本映射，以及重定向和删除标记的入口。每条知识的 `entryId` 创建后不因标题或路径变化而改变；详细元数据和受管正文保存在 `entries/<entryId>/revisions/<revision>/` 的不可变版本中。元数据记录类型、状态、新鲜度、正文摘要、来源定位与版本、关系和生成依据；外部来源条目不保存另一份可编辑原文。读者固定清单版本后只读取该版本引用的内容。

实现采用不可变依赖先写、manifest 最后原子发布的方式：中断留下的未引用版本不进入读取，不额外引入 `transactions/` 事实源。拒绝来源与撤销都发布新版本并保留操作记录，不回退全局版本号。独立的 `indexRevision` 只在条目变化时推进，维护队列状态变化不重写全文索引。manifest 和单条元数据发布前检查 4 MiB 上限，超限保留旧版，不写出下次无法读取的清单。

来源适配器统一接收项目绑定、来源身份和请求版本，返回来源身份、实际版本、受预算限制的快照或明确状态：可读、已变化、不存在、无权限、历史版本不可用。文件以内容摘要定位版本；Canvas 以真实节点内容 revision 定位；接口以服务提供的请求/catalog revision 定位；Vault 以授权资料根身份及笔记摘要定位。无法读取历史版本时不悄悄返回当前内容。Vault 必须由用户显式登记到项目的资料范围，不能将全局发现的 Vault 全部加入索引。

项目迁移、解除关联、删除、备份和磁盘清理须同步处理知识库归属。会话清理不得删除项目知识正文；项目删除入口需准确说明托管资料的影响。删除历史会话后，已确认知识不会暗中跟随删除，引用显示原始会话不可用；不保留隐藏的完整会话副本。

## 5. 新项目扫描建库

用户发起项目扫描后，自动完成授权范围内的登记、分类和有证据的知识补全，无需逐篇确认普通新增内容。

1. 识别项目根、子项目、manifest、脚本、测试配置、已有规则、文档和资产目录。默认排除依赖、构建产物、版本控制内部目录、凭据与密钥。
2. 优先登记已有资料，并识别重复来源。关联同一文件不生成第二份可编辑正文。
3. 提取项目总览、模块与目录说明、声明的运行命令、技术栈和接口索引。没有运行过的命令不能标为验证通过，读取到的配置不能证明线上状态。
4. 对业务流程、架构职责和改进规范生成带依据的草稿。市场需求、产品目标或设计理由缺少证据时列为缺口。
5. 展示本轮新增、更新、待确认、冲突、跳过与未覆盖范围，保留取消和续扫能力。

没有源码的空项目从用户已提供的规划与资料建立目录，不伪造技术栈、接口或业务事实。后续导入代码时增量扩充同一个项目知识库。

通用文件扫描与监听硬排除 `.proma/**`、索引缓存、事务与暂存目录；受管条目从已发布 manifest 进入索引，Canvas/API 只通过受控适配器登记。禁止跟随符号链接和读取多硬链接的来源文件。扫描和读取均验证真实根、文件身份和读取后版本，不能将文件名安全等同于正文没有敏感内容。

目录发现与内容提取分别记录水位。启动恢复、监听异常和“更新知识”会对已授权根执行可续跑的分批枚举以发现离线新增项，只对差异项重新提取；不在新会话中枚举整个项目。未初始化的项目不会因后台恢复自动建库。大目录分批让出事件循环，遇到权限或资源预算限制时显示未覆盖范围。

## 6. 当前 Agent 中的知识提炼

### 6.1 入口与范围

知识库不再单独选择模型。点击“更新知识库”后，先等待本项目来源扫描完成，再复用同项目普通 Agent 会话；没有合适会话时创建同项目会话并继承 Agent 选择。任务显式引用 `knowledge-maintenance` Skill，经现有 `after_current` 队列提交，不中断正在执行的任务，也不覆盖输入框草稿。扫描取消、失败或项目切换后不能提交迟到任务。

普通前台标准 Agent 在当前用户回合中按需加载同一 Skill，保存有长期价值的用户明确声明并处理一小批变化来源。Automation、委派、外部渠道、内部子会话及受限运维模式不因此获得知识维护权限；计划模式只能读取。新会话不因这一能力枚举整个项目，空闲时也不启动另一套模型。

### 6.2 来源与证据

`proma_knowledge_maintenance_next` 仅返回待处理来源的小批元数据。Agent 通过 `proma_knowledge_read` 取得固定版本正文后，使用 `proma_knowledge_submit` 提交带逐字引文的候选；未实际读取的来源或页不能作为证据。每回合最多处理四个来源，正文读取与检索共享累计预算。

对话候选只引用当前已持久化的真实用户消息，工作区、会话和消息身份由宿主固定，模型不能指定其他会话或伪造消息。提交前与发布事务内均复核消息身份、摘要及原文；用户删除或改写消息、切换项目、停止回合或进入计划模式时，迟到提交被拒绝。首次有效对话候选可创建空知识库，无需先扫描文件。

文档提炼默认是草稿；当前用户完整明确声明可作为对应决定或偏好的依据。Agent 的建议、总结和“已完成”声明不能自证事实。只读来源索引数、已读字节数与发布知识数分别记录，普通闲聊或重复信息允许零新增。

### 6.3 提交与增量维护

写入由主进程知识服务执行，持有项目写租约与事务锁，重新验证项目绑定、运行代次、权限、来源版本及人工修改基线。来源更新而结论不变时刷新依据并保留确认状态；人工改写正文不能被旧候选覆盖或重新背书。冲突保留待核对状态，不能只按时间新旧覆盖规则。

同一逐字引文已形成的知识若被模型改写措辞，首版保守跳过，不自动覆盖或替代人工正文；语义新增应引用实际新增依据，不能仅靠来源 revision 变化绕过此边界。

来源处理水位随 manifest 原子发布。未变化版本无需再次提炼；引用锚点保持稳定，拒绝与撤销记录不会因为换标题、改写措辞或模型升级而失效。显式 `proma_memory_record` 继续使用可恢复操作日志，Skill 避免将同一结论再复制到受管知识正文。

当前 Agent 工具回执与正常消息队列展示实际进度，只有收到发布回执才报告已保存。任务中断前已发布的知识保留，不把取消当作回滚。完成回合后不再调度后台模型，不递归启动维护 Agent；旧独立维护队列在恢复时停用并保留知识、水位和排除记录。

## 7. 索引与新会话加载

建立三层索引，各司其职：

1. 项目概览：项目定位、主要模块、当前已确认约束和关键入口。只保留短摘要与链接。
2. 主题目录：标题、分类、别名、适用范围、来源与状态，用于定位候选；不把整份目录固定注入每次对话。
3. 正文检索索引：按章节切块，关联稳定资料身份、内容版本和原文位置。索引属于缓存，原文才是依据。

首版使用本地关键词与倒排检索，结合标题、标签、路径、正文及显式引用关系排序，不引入向量数据库。检索先限定项目与访问范围，再处理相关性；当前有效内容默认优先，历史决策在用户询问历史时可检索。

新会话先取得简短项目概览；收到具体任务后检索相关主题，先给摘要，再按需读取命中章节。初始工程预算为概览最多 1200 个字符、摘要最多 6 项、单次正文返回最多 24 KiB UTF-8，均明确标记裁剪；后续读取按任务继续分页。预算由同一配置管理，实施验收后再依据真实项目调整。

检索由宿主保证：普通前台标准 Agent 每个用户回合开始时，宿主基于当前任务对已建立知识库执行一次本地检索，将相关结果作为低信任资料加入用户上下文；不存在知识库时直接返回空结果。Agent 通过工具扩展检索和读取章节。检索不触发扫描或付费模型调用，不为凑足六项注入无关内容；全回合有累计读取预算，必需规则仍走独立指令解析器。

这些预算只约束知识检索，不削减现行指令解析器确定的必需规则。知识文档不因被检索而取得系统指令优先级；新增规范须通过既有规则生效路径处理。

索引使用内容摘要与版本失效，不因 mtime 单独变化而重做模型分析。文件事件合并去抖，后台仅更新受影响条目。缓存丢失时可分批重建，页面仍可按已知目录浏览并显示索引进度。重启补偿只检查登记来源和未完成任务，不在每次新对话重新遍历项目。

检索命中在读取原文时复核版本。摘要已过期、来源已删除或正文被截断时如实返回，不能继续将旧摘要标为当前事实。新会话可取得待提炼来源数量，不承诺已经吸收全部最新对话。

## 8. 目录与文件的持续整理

目录整理服务于检索和阅读，不以频繁改名或移动文件表现“维护”。条目稳定身份与磁盘路径分离，目录变更后仍可解析旧引用。

自动整理可以更新分类、标题别名、主题索引和反向引用；对于知识库管理的文档，可以拆分混合主题、合并完全重复内容、归档明确被替代的版本。语义近似但含义不同的内容只提出合并候选。

主题包含三个以上可独立命名的子主题，或单篇长度已影响有界读取时，进入整理评估。阈值只用于发现候选；没有合理拆分边界时保持原文。整理优先在同主题多次更新后或用户空闲时批量执行，不在每条消息后移动文件。

修改正文或路径时保留前版本、来源映射和旧引用跳转，并同步主题索引。合并不能丢失适用范围、相反结论或人工批注。已归档内容退出默认新会话检索，但仍可搜索历史。

每次整理创建不可变操作记录，包含整理前后条目及 revision、旧新路径、章节与来源映射、引用重定向表和可恢复目标。拆分后旧条目指向子条目集合及原版本；合并后旧身份指向合并条目并保留各自出处。新正文、映射、目录与引用在同一清单提交中发布。撤销整理也创建新提交；若整理后已有人工修改，则按最新基线合并恢复或报告冲突，不能用旧快照覆盖后续工作。满足自动整理范围的操作直接执行并可审查，不增加逐次批准步骤。

项目原有文档、用户手写规则及 Canvas/API 的受管数据不由整理器自动移动、覆盖或删除。对现有 `memory/`，首版更新来源索引，提供带原版本和章节边界的整理预览；用户在原记忆编辑器中手动采纳。自动拆分、完全重复合并与撤销仅适用于知识库管理的不可变正文，首版不提供历史记忆整库自动迁移。

## 9. 用户入口与可观察结果

- 项目入口打开知识库完整视图；Agent 右侧“知识”标签复用同一数据与阅读组件。
- 顶部搜索覆盖资料、资产、决策和协作记忆，结果明确显示内容类型、来源和状态。
- 扫描入口统一为首次“扫描建库”和之后“更新知识”，展示真实进度、范围、结果和失败重试。
- 自动维护成功后提供简短更新记录，可查看差异、依据、撤销或纠正；无变化不重复通知。
- 知识详情展示引用与被引用关系；目录整理记录展示移动/合并映射及恢复入口。
- “本次使用的知识”按需展开，列出实际读取的资料与版本。不能只因命中搜索结果就宣称已经读过。

## 10. 关联模块影响

Agent service 负责可信回合边界；编排器负责提供持久化与证据快照，不在流式 token 热路径加入全量扫描。知识维护服务独立负责候选校验与提交，避免继续把业务堆入编排器大文件。

主进程知识服务、共享类型、IPC、preload 与 renderer 必须同步建立合同。对外工具可提供检索、按章节读取、引用和候选更新，方法说明放默认 Skill；工具仍承担路径、作用域、版本与权限校验。

复用现有 Markdown 编辑、预览、文件监听和原子写设施；同步更新知识维护 Skill 的职责并递增版本，避免当前 Agent 提炼与原记忆提示重复记录。现有记忆页逐步成为知识库中的记忆视图，原路径和旧数据继续可用。

Canvas、接口工作台、Vault、协作记忆通过窄适配器接入，保持各自权限和版本语义。接口索引只读取许可的说明及结构，不纳入凭据或原始敏感响应。

来源文本始终作为资料处理，提炼器不得执行文档中的指令；凭据、私钥和用户明确排除的内容不进入普通检索或模型输入。不会为实现提炼而建立跨项目全局知识权限。

## 11. 分阶段交付

第一阶段按三个可独立验收的节点交付，顺序执行并持续推进，不缩减最终目标：

- 1A：项目目录、原文件与记忆引用、基础分类和本地检索、可取消扫描、版本复核，以及新会话宿主检索与阅读工具。复用现有记忆入口和编辑能力。
- 1B：当前 Agent 调用 Skill 增量提炼、来源按需读取、显式记忆的可恢复关联、纠正与冲突。复用当前模型与队列，取消独立维护设置及后台模型调度。
- 1C：可审查、可撤销的受管目录分类与拆分合并，保留来源和引用，历史混杂记忆迁移有独立预览。

通过 Markdown、文本和已有模块引用先打通全链路；其他格式先支持登记和既有预览。1A 完成不能等同于对话持续维护已经完成。

第二阶段增强 PDF/Office 正文提取、图片 OCR、更多外部来源刷新与更精细的资料影响关系。每类新来源单独定义权限、预算和失效方式。团队实时协作、自动外部发布和跨项目共享不纳入本次首版。

## 12. 验收场景

首版实际工程预算：文件事件合并 500 ms，启动延后 10 秒开始恢复，15 秒调度检查、5 分钟目录补偿；每轮最多登记 5000 个来源，目录遍历每 100 项让出事件循环，读取最多 8 并发。单文件索引提取最多 256 KiB，总索引预算 16 MiB；正文每页最多 24 KiB。每个 Agent 回合累计最多 12 次读取、96 KiB 结果，初始上下文最多 24 KiB。当前 Agent 每回合最多提交四个来源，当前用户候选最多六项；模型费用、停止与队列沿用会话既有行为，不再运行独立后台模型。此前提出的“事件后 2 秒”“取消后 1 秒”是性能目标，本轮未以真实 GUI 和供应商执行测得，不作为已达成承诺。

扫描覆盖度分别统计已登记来源数、已核验来源数、已提取正文数、因预算/权限/失败跳过数；只有本轮登记范围枚举结束，才显示该范围扫描完成。外部新增但尚未发现的资料不计入“全部内容已覆盖”的承诺。

1. 新项目含 README、manifest、接口和图片时，扫描能登记来源并生成可追溯项目说明；缺失市场资料时显示缺口。
2. 已有人工文档和规则保持原文；自动规范建议不直接变为生效指令。
3. 用户在正常对话明确改变产品决定后，新会话检索到新决定、原理由与替代记录。
4. Agent 提议尚未被采纳、用户只是引用他人观点或工具执行失败时，不生成已确认项目事实。
5. 同一回合重试、应用重启和显式记忆工具与 Agent 提炼并存时，不重复保存同一结论。
6. 两个同项目会话并发更新同一知识时，保留双方增量或报告冲突，不发生后写覆盖前写。
7. 用户取消、切换至计划模式或撤销来源授权后，迟到分析不能提交；测试覆盖最终发布边界的证据变化，不重新执行用户主任务。
8. 修改来源文件后，关联摘要显示待复核；命中旧索引时重新校验版本，不冒充最新内容。
9. 在含大量文件和超长文档的项目中新建对话，不全量读取知识正文；实际注入符合预算且无关文件不被读取。
10. 外部命令修改文件、监听丢事件或缓存删除后，增量补偿/重建可恢复，不需要全量重新调用模型。
11. 拆分、合并或移动受管文档后，原引用仍可解析，来源和人工批注保留；恢复操作遇到后续人工修改时不会覆盖新内容。
12. 项目迁移、会话归档清理与数据根切换后，长期资料仍能正确定位；删除项目准确处理其托管资料。
13. 索引或多文件提交中途崩溃，重启后得到完整旧版本或完整新版本，不出现正文与清单互相指向错误版本。
14. 项目 A 的对话和检索无法读取项目 B 未授权资料；含诱导指令的来源文本不能影响提炼器权限。
15. UI 能区分已登记、已提取、待确认、待复核和索引未完成，不以文档数量或未经定义的“完整度百分比”代替覆盖证据。
16. Canvas/API/Vault 来源被删除、撤权或指定历史版本不可用时，返回对应状态；不读取其他项目、不退回当前版本冒充历史。
17. 同一真实目录关联两个工作区或复制后以新 ID 导入时，知识归属冲突明确返回，不覆盖原 manifest 或继承维护授权。
18. 应用关闭期间新增文件、监听事件丢失后，目录发现补偿能登记新来源；知识库自身发布不产生新的扫描候选。
19. Agent 未被显式要求查知识库时仍取得相关依据；后台排队和预算耗尽时能补读有界近期纠正，不把原始消息标为已确认事实。
20. 显式记忆在正文与关联提交之间退出，恢复后不重复沉淀、不覆盖人工改动；撤销候选在重试和提炼器升级后不会自动复活。

效果验收使用固定项目样本，覆盖中文提问/英文文档、别名、旧决定与新纠正；记录相关证据召回、前六项无关比例、错误事实晋升、纠正可见延迟和累计读取量。关键未采纳/失败/转述反例要求零误晋升，不能仅用索引条数证明检索有效。

实现验证采用 BDD 定向测试，优先覆盖状态、权限和实际读写边界，再执行 Bun 类型检查和 Electron 构建；执行结果见实施计划。上述列表同时保留后续产品效果验收目标，不等于每一项已做真实 GUI、供应商或跨平台验收。

首版接入项目文本、原 memory、Canvas 文本和接口工作台的受控元数据；图片、PDF、Office 目前只登记元数据，Vault 尚无项目范围授权绑定，暂不自动接入。扫描完成的是现有资料分类、可检索片段和覆盖状态；跨文件业务说明、规范建议仍需在普通项目对话中基于证据生成，再经维护管线沉淀，扫描本身不静默调用模型补写未知业务。知识详情已有来源、版本及整理记录，独立的“本次使用的知识”汇总面板、完整反向引用图和真实项目检索质量基准仍未交付。
