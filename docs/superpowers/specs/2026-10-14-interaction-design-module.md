# DutyDeck 交互设计模块：业务定义与原型提案

日期：2026-10-14。
状态：**设计提案，非已实现产品**；本文用于业务边界与交互评审，不是实施任务计划。
配套原型：[交互设计工作台](../../prototypes/interaction-design/index.html)。

版本说明：本文保留最初业务定义和 V1 验收记录；第 5 节布局已由[当前 V3 说明](2026-10-14-interaction-design-v3.md)取代。正式功能对齐、Agent 合作和资源路径以[模块对齐计划](../plans/2026-10-14-interaction-design-alignment.md)为准；下文的 Canvas 版本/导出复用设想不能理解为直接沿用其 node 身份或资产生命周期。

## 1. 业务定位

在当前项目内，把一句产品想法逐步变成可点击、可修改、可验证、可交接的 App / Web 原型。
用户能在写业务代码前确认页面结构、关键路径和主要状态，再决定哪些设计进入实现。
Agent 承担结构整理、页面生成、局部修改和检查；用户保留方案选择与采纳权。

模块主要解决三个问题：

- 只有文字需求或静态设计图，无法体验完整流程，交付后才发现路径断裂。
- AI 每轮重新生成整页，容易丢掉已确认布局、手工修改或业务约束。
- 原型、聊天和版本相互脱节，开发者不知道应当实现哪一版、哪些功能只是模拟。

成功结果是用户能完成一条目标任务，并明确交付版本、模拟范围和未解决问题。
页面数量或生成图片数量不能代替业务完成度。
原型不是生产系统；真实鉴权、支付、服务器部署和原生安装包不在首版交付承诺内。

## 2. 服务对象与主要使用场景

| 用户 | 想完成的工作 | 模块提供的结果 |
| --- | --- | --- |
| 独立开发者 | 把想法变成能试用的产品流程 | 可演示的原型与明确的实现边界 |
| 产品负责人 | 验证需求是否自洽、页面是否齐全 | 页面结构、交互路径、遗漏状态及可评审版本 |
| 设计师 | 快速比较方向，再精修重点页面 | 风格候选、局部属性修改与保留约束的迭代 |
| 前端开发者 | 理解被采纳方案并开始实现 | 可运行 HTML、资源、交互说明与检查记录 |

一个 DutyDeck 项目可以包含多个原型，例如同一产品的 App、管理后台和独立探索方案。
修改当前原型默认沿用其身份；只有明确创建独立方案才新增原型，避免每轮对话产生新项目。
原型可以由多个会话继续处理，但每次修改必须携带明确的原型与版本引用。

## 3. 核心业务对象

| 对象 | 定义与归属 | 关键约束 |
| --- | --- | --- |
| Project | 既有 DutyDeck 项目，提供权限与业务上下文 | 原型不能越过项目授权边界 |
| Prototype | 项目内一个独立原型，包含目标、平台与入口页 | 多原型并存，不默认合并 |
| Page | 可独立选择、预览的页面，包含布局和状态 | 页面 ID 稳定，标题可修改 |
| Element | 页面内允许识别和编辑的按钮、文本、输入等元素 | 通过稳定 ID 定位，不依赖模糊文案匹配 |
| Flow | 用户动作、条件、页面跳转与状态变化的独立描述 | 不占用 Canvas 素材关系的语义 |
| Revision | 一次完整、可追溯的原型内容快照 | 页面、资源与交互关系版本一致 |
| Delivery | 从指定已采纳版本生成的交付包及证据 | 后续编辑不改变已交付内容 |

运行记录另外关联发起会话、输入版本、修改范围与结果，不把运行状态混成原型内容。
演示中的输入、计数和打卡结果属于临时状态；重置演示不会删除设计或版本。

## 4. 用户完成一项设计的流程

1. **Brief**：说明目标用户、要完成的任务、App / Web、参考资料和约束。
2. **页面结构**：Agent 提出页面列表、入口及主要路径，标出缺失信息。
3. **生成草稿**：根据结构生成可运行候选，明确哪些内容和数据是模拟的。
4. **局部编辑**：选择页面或元素，直接修改允许字段，或将范围带入主会话。
5. **演示检查**：按真实操作体验路径，检查输入、返回、空态和失败处理。
6. **采纳**：对比候选及当前版，采纳匹配当前基线的方案。
7. **交接**：导出已采纳版本、资源、交互说明、已检查项和剩余问题。

页面结构可以先由 Agent 草拟，避免用户填写冗长表格。
涉及目标用户、主要业务路径等关键缺口时集中澄清；样例文案、图标等可用明确假设推进。
用户随时可以回到任一步，但后续生成不能静默撤销已保存的修改。

## 5. 工作台布局与模式

宽工作区采用顶部工具栏、左侧页面导航、中央预览、右侧属性区。
顶部提供当前项目与原型、设备预览、编辑 / 演示、版本及交付入口。
左侧显示页面缩略图、入口页、页面名称；流程视图展示页面间主要任务路径。
中央以页面为单位预览；总览用于比较页面，不同时运行全部页面脚本。
右侧依次展示选中对象、允许修改的属性、点击动作和可送入主会话的上下文。

**编辑模式**：点击可编辑对象选中元素，不执行其业务按钮行为；选中反馈清晰可见。
**演示模式**：点击执行原型真实交互，不弹出属性选择；有独立返回和重置演示入口。
切换模式保留选中页面；演示状态是否重置必须有明确行为，不能悄悄修改设计内容。

DutyDeck 右侧面板可能很窄，布局应按容器宽度适配，而非只看浏览器窗口宽度。
窄面板使用页面选择器与属性抽屉，提供展开工作区入口，不把三栏等比压缩。
主要按钮、页面切换、关闭抽屉与版本选择应能用键盘操作，焦点位置可辨认。
空项目显示创建入口；生成中、失败、取消、无选中元素均有独立空态或状态说明。

## 6. 本轮可点击原型的评审范围

配套交互稿采用习惯 App **「拾光」**，展示四个页面的设计工作流：

| 页面 ID | 页面 | 可体验的业务行为 |
| --- | --- | --- |
| welcome | 欢迎与开始 | 从入口进入今日习惯 |
| today | 今日习惯 | 查看本地样例进度，进入习惯详情 |
| detail | 习惯详情 | 查看目标、完成打卡并进入反馈页 |
| done | 完成反馈 | 返回今日列表，看到本地状态变化 |

原型应让评审者区分“工作台的操作”与“工作台内 App 的操作”。
页面切换、编辑 / 演示、允许字段修改、主路径跳转和本地状态反馈属于实际交互。
Agent 回复、生成等待、版本提议与自动审查属于**明确标记的模拟体验**。
模拟候选只用于说明未来采用流程，不代表已调用模型或形成真实生产版本。
所有样例数据仅在原型内使用，不接触真实用户项目、账号或业务存储。
最终实际通过哪些交互由浏览器验证记录确定；本节描述目标，不代替测试结果。

## 7. Agent 能达到的效果

| 层级 | 用户表达示例 | Agent 的目标输出 | 可靠边界 |
| --- | --- | --- | --- |
| 需求整理 | “做一个鼓励每日阅读的 App” | Brief、页面结构、任务路径与假设 | 用户确认目标；不凭空断言市场需求 |
| 首稿生成 | “按这个结构生成可点击版本” | 页面、样例数据、导航和基础状态 | 可运行仍需检查，不等于已验证 |
| 局部修改 | “保留布局，让这个按钮更明确” | 指定元素范围的候选改动 | 必须定位元素与基线，不能误改其他页 |
| 风格探索 | “保留结构，比较两种温暖风格” | 可对比候选和锁定项说明 | 不保证不同页面天然一致，需对比确认 |
| 流程补齐 | “没有数据和失败时怎么办” | 空态、错误态及恢复路径候选 | 根据明确业务规则，不发明真实接口 |
| 辅助检查 | “检查注册到首页是否能走通” | 可执行检查、结果与问题列表 | 自动通过只代表实际覆盖的场景 |
| 交接整理 | “把采纳版本交给前端” | 固定版本的资源、说明和证据 | 不承诺生产后端、上线或 native build |

首版价值是降低“说明需求—得到可试用设计—修正”的往返成本，不给出虚假准确率或时间保证。
Agent 能提出缺失状态和设计建议，但不能替代真实用户研究、无障碍审计或专业业务判断。
截图可用于理解视觉参考；不能因为识别了截图中的按钮，就声称还原了真实交互。

## 8. Agent 与用户手动修改的协作合同

Agent 沿用 DutyDeck 主会话，不在属性栏另建一套孤立聊天历史。
“让 Agent 修改”附带项目、原型、页面、元素、基线版本、用户指令与锁定项。
请求涉及整条流程时，应明确范围包含哪些页面与动作；页面级请求不默认扩展到全项目。
候选结果展示改动范围、依赖变化、检查结果及未验证项，用户可预览、采纳或继续修改。

手动属性修改与源码修改必须更新同一个权威内容事实源。
属性区是权威内容的受控投影，不能另存一份与源码逐渐漂移的组件树。
首版只允许稳定元素 ID 下声明过的字段，例如文字、颜色、间距和已定义动作。
无法可靠映射的 HTML 以源码或 Agent 修改为入口，不承诺任意 HTML 的全量双向可视化编辑。
源码删除或重构元素后，对应旧选择失效；不得按相似名称自动选中另一个对象。

用户在生成期间修改了基线，返回结果标记过时，仍可比较，但不能自动覆盖当前草稿。
关闭面板、切换原型或切换会话后，结果归原目标，不抢占新目标或恢复已关闭面板。
重新应用旧候选时需重新检查当前版本及受影响范围；必要时生成新的候选。

## 9. 状态定义与恢复

运行状态与内容状态分开表达，避免“生成完成”等同于“设计已通过”。

| 状态 | 含义 | 用户下一步 |
| --- | --- | --- |
| 生成中 | 请求正在处理，已固定目标与输入版本 | 查看进度或取消，仍可查看当前版 |
| 候选 | 已生成可查看结果，尚未采纳 | 演示、比较、修改或采纳 |
| 已采纳 | 当前被选定用于后续设计或交付的版本 | 继续编辑、回看历史或导出 |
| 过时 | 输入基线与当前版本不一致 | 保留候选，比较或重新生成 |
| 失败 | 本次运行未形成可采纳的完整结果 | 查看原因并重试，当前版不丢失 |
| 已取消 | 用户终止了本次运行的继续处理 | 保留当前版，需要时重新发起 |

取消后迟到的结果不能变成已采纳版本；可保留的诊断或片段必须标明不完整。
检查结果绑定具体版本；改动后受影响的检查失效，不沿用旧“通过”徽标。
撤销用于当前编辑操作，历史恢复用于采用旧快照；两者都不能删除后续历史证据。

## 10. 首版范围与后续能力

首版支持 App / Web 目标、当前项目内多原型、多页面清单、入口及独立交互关系。
内容为可运行 HTML 沙箱与本地资源；输入、弹窗、页面跳转和样例数据在受限运行时演示。
页面清单与内容快照一起版本化，交付时不出现新页面引用旧资源的混合版本。
支持受控元素编辑、主会话定向修改、候选比较、采纳、失败恢复与交付检查。
HTML 可运行不等于原生 App；App 模式首先模拟移动界面与操作流程。

后续可评估组件复用、设计变量库、多角色任务路径、批量风格比较与更深入的响应式检查。
导入复杂外部工程、任意 DOM 编辑、真实 API 联调、多人实时编辑各有独立边界，不默认纳入首版。
不直接移植上游的整个 Next.js 服务端，也不为编辑器新增常驻本地服务器。

## 11. 与现有业务的兼容及性能

优先复用现有 Canvas HTML 工作台的沙箱、版本与导出能力，以及截图服务的缓存和串行调度。
现有服务依赖 Canvas 目标身份；复用时需要适配原型身份，不能只换 UI 名称就假定合同兼容。
当前预览 CSP 阻止网络和表单外发；交互原型应优先使用本地状态及受控内部导航。
需要新增运行能力时单独核对授权边界，不为实现页面跳转直接放开外部网络或顶层导航。
现有 Canvas 的四类关系继续表达素材与生产语义；页面路由使用独立 Flow，不混用。
legacy Canvas 保持原来的存储和入口，不批量迁移或改变既有图片生产、编排与会话恢复行为。

持久化遵循项目本地优先合同，采用可移植文件与既有原子写封装。
新接口同步检查 shared 类型及通道、main handler、preload bridge、renderer 四层契约。
UI 复用现有 Radix/shadcn 与主题变量，不引入另一套主题或状态管理体系。

资源策略为只运行当前页面，其他页面显示带版本身份的静态缩略图。
编辑仅刷新受影响内容，截图受控排队并复用缓存，隐藏工作台释放不再需要的运行资源。
页面数量增加不应线性增加常驻 iframe、离屏窗口或模型请求。
快照、资源和历史需要可见的保留策略；不能无上限复制大资源或静默删除用户历史。

## 12. 可评审验收标准

- 能明确指出当前项目、原型、页面和版本；切换目标不会串用状态。
- 从欢迎到今日、详情、完成再返回的主路径可操作，本地打卡状态正确反馈。
- 编辑模式选中按钮只触发选择；演示模式同一按钮执行预期动作。
- 允许字段修改能在预览中体现；非法或失效元素引用得到清晰提示。
- 生成结果作为候选展示，采纳行为明确；手动修改后的迟到结果不能覆盖当前版。
- 失败、取消和过时有可理解的状态；重试不丢失现有设计。
- 窄面板仍能操作页面、属性与演示，深浅主题和键盘焦点可辨认。
- 检查记录列明版本、场景、结果和未覆盖项，不能把模拟审查当成测试通过。
- 交付包固定到已采纳版本，包含 HTML、所需资源、交互说明和验证证据。
- 交付说明明确模拟数据、后端缺口及未验证平台；离开 DutyDeck 的运行方式需实际验证。

## 13. 主要风险与决策理由

最大的风险是把视觉编辑器误当成任意页面的可靠结构编辑器；受控字段让首版能力可验证。
第二个风险是自动生成覆盖人工修改；基线检查与候选采纳让用户始终知道当前方案来自哪里。
第三个风险是把漂亮画面当成完整业务；任务路径、状态覆盖与交付证据共同定义完成。
第四个风险是复用 Canvas 时改变其他业务语义；保持身份、关系与 legacy 边界减少回归范围。
模型输出质量、复杂页面性能及真实用户可用性需要后续实测，不由本轮交互稿推断。

## 15. 本轮原型交付与验证

原型由 `docs/prototypes/interaction-design/` 下的 HTML、CSS、JavaScript 构成，无外部依赖。
只在浏览器独立缓存中保存示例；当前评审稿一次展示一个原型，新建前可导出保留当前内容。
本轮没有接入真实 DutyDeck 项目文件、模型、Canvas 或生产业务，也没有实施第 10 节的完整首版。

Chrome 浏览器 **34 项交互检查通过，页面脚本错误为 0**：
