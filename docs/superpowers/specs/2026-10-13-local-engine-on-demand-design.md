# DutyDeck 本地引擎按需安装设计

## 结论

DutyDeck 不默认下载或启动 `llama.cpp`。用户在“设置 → 关于/更新 → 可选环境能力”中主动安装一次受管本地运行环境；环境校验通过后，模型配置页才解锁 GGUF 模型下载。Ollama 继续由 Ollama 管理环境和模型，两个运行时的下载职责保持分离。

## 用户流程

1. 打开 DutyDeck 本地运行时，看到当前平台、固定引擎版本、下载大小、许可和磁盘预留。
2. 在“关于/更新”页点击“安装运行环境”，确认后开始下载；界面显示下载、校验、安装、失败和取消状态。模型供应商详情页只展示引擎状态，并提供返回入口，不重复安装操作。
3. 引擎进入“已安装”后，模型目录按钮才可用；用户选择 Qwen/Gemma 等模型并下载。
4. 模型校验完成后，继续执行加载、能力测试和启用。测试不自动启用模型。

## 主进程边界

- 引擎来源、版本、平台、架构、归档大小和 SHA-256 固定在受信清单中；renderer 只能传递“安装/取消”操作，不能传入 URL、路径或命令参数。
- 归档先流式下载到 staging，再校验归档摘要；解压时拒绝绝对路径、越界路径、设备文件、未允许的链接和超出解压上限的内容。
- 安装目录按 `活动数据根/engines/llama.cpp/<版本>/<平台>-<架构>` 隔离，manifest 与二进制一起原子发布；失败不覆盖上一份可用引擎。
- 应用启动时优先使用已校验的用户引擎；若安装包未来携带同版本引擎，可作为只读预置资源，但 UI 仍明确标注来源。
- 引擎下载取消、校验失败或资源不足时，模型下载保持锁定，不能静默回退到云端或 Ollama。

## 性能与影响

引擎只下载一次，多个 GGUF 模型共享同一版本，减少重复磁盘占用。首次安装会增加一次网络等待和解压 CPU 峰值；采用 staging、流式进度和原子切换避免半成品被加载。模型运行时仍保持单模型加载，避免与其他 Agent 任务争抢内存。

## 验证范围

覆盖引擎清单校验、断点/取消、损坏归档重试、路径穿越防护、安装状态恢复、模型按钮解锁和 Ollama 外部流程隔离。真实引擎归档、真实 GGUF 推理和跨平台签名需在可联网构建机及目标平台继续验证。
