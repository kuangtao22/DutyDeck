# 知识库大纲提炼可靠性优化方案

日期：2026-10-12。状态：已按用户“请开始吧”实施；离线验证结果见实施计划，未执行真实模型语义实验。

## 目标与依据

目标是让用户确认整理范围后，尽早得到可阅读、有来源依据、达到内容准入标准的主题文档；局部问题有明确原因与恢复入口，继续时复用已完成成果。2026-10-12 用户追加要求：同时评估重要内容、业务完整性和是否值得保存，不能只判断执行链路和文件是否写成。

2026-10-12 对“续命”整理会话 `7e42f69b-8b53-4f21-860b-c46d35e0dd54` 的核查发现：两轮累计约 29 分钟，仅保存索引和三个 pending 大纲项，未调用正文发布工具。生成回合传入的来源版本号缺一位，工具按版本不匹配返回 changed，Agent 将其解释为文件变化并停止全部正文生成。提案曾多次引用错误，最终以空 sources 提交。完整回复明确说明正文未生成；界面显示知识 0 条符合磁盘状态。

本轮进一步检查发现，`proma_knowledge_status` 工具支持 offset，但 `project-knowledge-agent.ts` 的 facade 未向 maintenance.status 透传 offset；方案包含该分页缺口。此前 90 项相关回归通过，只能证明已覆盖的合同，不能证明真实模型完成能力。

成功标准：正常资料可以完成正文保存、目录打开及新会话检索；一项出错不会阻止无依赖的其他项；阻塞、暂停、预算用尽和已完成可以准确区分；重要业务结论有对应依据、语义类型和适用范围；尚未达标内容不会作为当前事实自动注入。事实可靠性仍须通过真实样本核查。

## 方案选择

| 方案 | 收益 | 代价与限制 |
| --- | --- | --- |
| 仅调整提示词和错误文案 | 改动较小，可提醒模型逐篇处理 | 仍要求模型反复抄录身份与版本，缺少可恢复执行记录，难保证稳定完成 |
| 宿主维护来源引用与执行进度，Agent 负责内容（推荐） | 减少参数错误、保留阶段成果、支持按项恢复 | 需要同步工具合同、持久状态、会话生命周期和 UI |
| 独立后台建库服务 | 可单独安排任务与模型预算 | 与沿用当前 Agent/模型的产品约束冲突，增加第二套调度与恢复逻辑 |

采用第二种，在现有知识服务、Pi Agent、写租约与会话队列内完成。默认顺序执行，不引入新依赖、数据库或独立模型配置。

## 1. 由宿主保存来源身份与版本

### 面向模型的引用

- 搜索返回短来源引用，例如 `src_k7m_7`，其实际值由宿主分配并映射到工作区、运行代次、entryId 和精确 entry revision；引用含不可复用的运行命名空间，不能每轮重置为相同的序号。
- 正式读取返回页引用，例如 `page_k7m_3`，绑定来源版本、页偏移和本轮实际读取内容。正文提交携带页引用及逐字 quote，宿主复用现有读页账本再次核验。
- 计划引用搜索得到的来源引用；提交时宿主解析并持久化真实 ID/revision，保留已有文件格式及来源追溯能力。
- 大纲变更使用状态工具发出的短流程引用；正文写入使用短目标引用，绑定已批准计划、大纲项和所见正文版本。宿主仍执行原有并发校验，不能把旧引用静默升级到最新版本。
- 短引用仅在所属运行有效；跨项目、跨运行和重启后的旧引用明确失效。恢复时依据持久来源身份重新发放引用、重新读取必要页，不恢复“模型已读”的虚假账本。
- 旧 ID/revision 参数保留兼容，校验必须与新入口等价；同一次调用只能采用一种表示。

这样减少模型复制长哈希的负担，并保留“读到哪个版本，只能用哪个版本”的约束。

### 可区分的错误

| 错误类别 | 宿主事实 | 恢复策略 |
| --- | --- | --- |
| 参数或引用无效 | 格式错误、引用不存在、跨运行或类型混用 | 返回具体字段与恢复操作；重新获取引用，最多一次自动恢复 |
| 所见条目版本过期 | 请求版本与当前条目版本不同 | 返回当前条目定位；重新读取，不能沿用旧引文直接提交 |
| 原文件实际变化 | 磁盘身份或正文与索引不一致 | 对已授权、已登记来源定向刷新，再读必要页面 |
| 目标正文被人工修改 | 正文版本冲突 | 阻塞该文档更新，保护磁盘内容；用户可以查看差异后决定 |
| 全局授权失效 | 工作区迁移、权限撤销、用户暂停/取消 | 停止本次任务的后续写入与自动续接 |

增加有界的定向来源刷新入口，只接受已登记来源引用，在原授权根与写租约内更新来源索引；默认每批至多 4 个。不会扩大目录范围，也不把重新索引视为已读正文。错误返回 code、作用范围、可恢复性与建议动作，UI 使用中文说明。

空 sources 不能作为来源引用失败的降级路径。确实只有用户指令、没有原始材料时，允许带有效用户证据的规划或明确标为“仅规划，待补依据”；实际来源引用失败则保留关联与失败原因。旧的空来源计划继续可读，在已确认范围内补齐来源映射，新增主题再确认。

跨轮用户证据单独处理：任务创建时仅登记本次任务中真实用户提供的事实消息，固定消息身份、内容哈希、工作区归属及来源类型。点击更新/确认时由宿主生成的控制提示不属于事实证据。续接只按已登记的精确消息身份重新读取并核验，向模型重新呈现原文并发放当轮引用；不扫描历史会话，也不放宽普通 Agent 只引用当前用户消息的规则。原消息删除、变化或工作区归属失效时，仅阻塞依赖该证据的文档。用户点击继续恢复执行额度，不等于再次确认原消息中的事实。

## 2. 按文档完成和恢复

处理顺序为：读取当前大纲项及相关来源 → 提炼并执行第 7 节的内容准入检查 → 保存达标正文或待补草稿 → 收到宿主成功回执 → 处理下一项。避免先读完所有资料才集中写入。

- 当前范围内可以连续处理多项；每项完成立即保存可阅读正文与索引。
- 一份资料不支持某项时，记录具体阻塞，仅继续处理不依赖它的项。同一来源被多项引用时，标记所有受影响项。
- 未读完整、证据不足或部分章节待补时，可以保存有依据的部分正文，状态为 partial；不得用占位正文冒充完整知识。
- ready 表示本次大纲内容已生成，知识事实状态继续独立。宿主能核验来源、版本与持久化结果，不能仅靠程序校验保证所有论断语义正确。
- 保留同一个已授权整理会话，沿用其渠道/模型。宿主从已保存的条目和状态推导剩余工作，模型回复中的“完成”不更新权威完成数。

第一阶段即在大纲项上持久化最小来源依赖：每项关联实际来源身份、所见版本及必要的用户证据身份；区分依赖待确定和已确定。没有正文也能识别某一失败来源影响哪些项，不能用整个分组的来源列表代替逐项关系。旧空来源计划先在已批准主题内补齐依赖；关系未确定时不猜测是否独立。来源支持范围本身仍由 Agent 判断，宿主保证关系可追溯且引用真实。

### 持久执行状态

在现有 workflow 内增加可选的 execution 记录，包含整理会话、运行身份、代次、当前项、最后有效进展、按项失败原因和本次任务预算消耗。正文已有的 pending/partial/ready/missing 继续表示产物状态；运行状态单独表示 queued/running/paused/blocked/interrupted/finished。

只在开始、进入条目、正文提交、错误和回合终止等边界原子落盘，不按流式 token 写文件。宿主工具回执和会话生命周期更新 execution；模型可说明缺口，但不能自行标记成功。普通 Agent 回合结束不等于知识库任务完成。

finished 表示本次范围所有项达到 ready 且内容准入检查通过；计划、假设、历史记录可以按其类型达标，不要求把它们变成已证实的当前事实。仍有 partial/pending 项或准入阻塞时，用户暂停进入 paused，进程中断进入 interrupted，缺依据、恢复失败、额度耗尽或无有效进展进入 blocked 并记录原因；预算耗尽原因固定为 budget_exhausted。所有项都是 partial 也不能显示全部完成。不新增的低价值/重复项须在已批准主题内说明合并或保留来源的去向，不能通过静默缩小范围伪造完成；必要的范围调整仍经过原有计划确认。

恢复时，缺少活跃宿主运行的 running 记录转为 interrupted。已有正文保留；重新获取所需来源和目标引用后继续。相同工作区同一任务只允许一个有效写入执行者，双击或重复派发按任务身份去重，迟到回执不得改变新运行状态。

### 有界续接

由宿主沿既有会话队列续接，Agent 不递归创建维护任务。只在用户已启动的同一整理任务内自动继续。

建议首版默认：生成阶段最多 3 个 Agent 回合（初始回合加 2 次续接）；每回合沿用现有最多 12 次检索/读取、96 KiB 结果预算，因此该阶段总额不超过 36 次及 288 KiB。来源错误对同一项同一版本最多自动恢复一次。有效进展仅指本次任务新增读取的来源版本/页范围，或实际改变正文内容、证据或产物状态的成功提交；重复读取同一页、无变化提交和状态查询不计入，也不重置计时。回合终止仍有剩余项时，只有额度允许且存在有效进展才在既有队列续接。10 分钟活跃执行上限到达后取消本任务运行并保留进度，等待用户“继续未完成项”。这些是初始保护阈值，需真实样本校准，不是性能承诺。

预留正文提交与状态查询能力，检索预算用尽不阻止提交已经读到且仍然有效的证据。预算在任务级持久化，普通重启不重置自动续接次数；只有用户显式继续才授予下一段执行额度。模型推理另受既有输出上限控制；上述读取预算不等同于美元费用硬上限。

暂停首先阻止后续提交和续接，再取消该任务拥有的活跃 Agent run；不得取消同会话后来开始的其他任务。已经在写租约内提交成功的文件保留。退出/崩溃后默认显示可继续，不自动发起新的模型调用。

## 3. 来源覆盖与大纲质量

每项提供用途、适用对象/时间、章节、关联来源、信息缺口及与其他文档的边界。字段按内容需要展示，不为所有项目强制同一种目录或正文章节。

- 增加按 groupId/itemId 读取详情的能力；摘要状态保持小体积，来源、缺口和章节可以分页获取。修复 status 的 offset 透传，超过四项仍能完整遍历。
- 相同事实指定主要维护文档，其他主题按相对链接引用。例如产品文档维护产品边界，发布文档维护发布验收；必要的简短上下文可以保留。
- 来源覆盖区分“已登记、读过相关页、已被正文引用、尚未处理、暂不支持”；不能从文档数量推算资料覆盖率。
- 后续更新范围为新增、变化及首次未处理的已批准材料，避免未被抽中的重要资料永久遗漏。
- 日期敏感结论注明截至时间，历史冲突保留待核验状态；成功写入不把内容升格为用户确认的事实。
- 附件仍保存原格式；PDF/Office 等仅元数据来源显式标为待解析，不在本轮接入新的解析依赖。

## 4. 用户界面

沿用“左侧真实文件树、右侧正文、独立整理进度弹窗”。确认整理范围后不增加逐篇审批。

弹窗顶端展示任务状态、当前处理项、已保存数和阻塞数；例如“已保存 2/3 篇，1 篇待处理”。同时区分其中达到准入要求与仍待补证据的数量，不能把已保存草稿计入达标数量。每项可展开用途、章节、来源、内容准入结论与具体问题，已保存文档可直接阅读。

| 实际状态 | 提供的操作 |
| --- | --- |
| 正在运行 | 暂停、查看整理会话 |
| 用户已暂停 | 继续未完成项 |
| 来源或目标冲突 | 查看原因/来源/差异、仅重试受影响项 |
| 达到预算或运行中断 | 继续未完成项，保留已保存成果 |
| 全部完成 | 阅读文档；检测到新来源后提示更新 |

已有正文被外部删除时显示“文件已删除/不可用”，不能把 missing 一概称为“缺少依据”。内容待核验与任务失败分别展示。

主进程在有效状态变更后推送事件；renderer 按 workspaceId/run generation 过滤并合并刷新。保留低频轮询做补偿，隐藏窗口不额外轮询。任务结束后清理运行中提示，不依赖 paused=false 推断仍在生成。

## 5. 开销与关联模块

| 范围 | 影响与控制 |
| --- | --- |
| 模型上下文 | 搜索优先返回标题、摘要、短引用和必要片段；正文按需读。写入回执只返回当前项结果、最新目标引用和剩余数量，避免每次回传整份大纲 |
| 本地 I/O | execution 随现有原子事务落盘；定向刷新来源，索引按受影响条目更新；不为每项重新扫描整个项目 |
| 并发 | 首版串行生成，复用工作区写租约；不叠加并发模型或重复扫描 |
| Agent 生命周期 | 提供知识任务专属的开始/终止回调，沿现有普通会话队列运行；普通聊天、Automation、Collaboration 的完成语义保持各自边界 |
| 独立记忆 | 知识任务的暂停、失败及来源限制仅影响该知识任务；记忆保存、检索和用户偏好维护独立运行 |
| 旧数据与外部编辑 | 新 execution 字段可选；旧计划、大纲、正文身份和链接继续读取；外部修改仍按当前版本拒绝覆盖 |
| IPC 与权限 | shared 类型/通道、main handler、preload bridge、renderer 四层同步；新刷新工具和短引用解析复用模式/权限/工作区守卫 |
| Skill | 更新 knowledge-maintenance 指令与版本，明确逐项写入、有界恢复、真实回执与未读内容边界 |
| 内容准入与检索 | 检查与正文生成共用已读证据，必要补读计入原有额度；正文哈希与来源版本变化使旧评估失效。搜索、自动上下文、引用展开和 UI 均保留内容类型、有效期与准入状态，不能只在前端加标签 |

不预先承诺节省百分比。真实验证统计首篇可阅读时间、成功正文数、重复读取字节、引用失败次数、总耗时、Token 与有可靠单价时的费用，同时比较遗漏和错误引用。

## 6. 分阶段交付与验收

### 第一阶段：可靠引用、基本内容准入与逐篇产出

涉及 `project-knowledge-tools.ts`、`project-knowledge-agent.ts`、`project-knowledge-agent-maintenance.ts`、`project-knowledge/service.ts`、`project-knowledge/vault.ts`、`project-knowledge-ipc.ts`、共享合同及 Skill；短引用映射与错误解析放入有单一职责的辅助模块，避免继续扩大主文件。

验收：漏位或混用版本不能伪装成“原文件变化”；旧引用不能跨运行使用或因序号重用误命中；至少三份来源中一份错误时，无依赖的两篇能保存；同组两篇只有一篇依赖失败来源时精确隔离；已有正文不被覆盖；大于四项的大纲能完整取回；仅用户原话的合法提炼仍然可用。

内容准入不能推迟到第三阶段：首阶段同步记录关键业务结论与证据对应、内容类型、适用范围和阻塞原因，并落实待补草稿不进入默认事实上下文。真实引用但不支持结论、指标目标冒充实测结果、历史口径冒充当前规则、商业权益冲突，均不能因正文写成而显示达标。已读来源中的重要规则和例外必须列入覆盖检查。

### 第二阶段：执行状态与恢复交互

涉及知识 runtime/store、Agent 生命周期接入、shared/preload/IPC、`ProjectKnowledgeTab.tsx`、`KnowledgeWorkflowPanel.tsx` 和 `KnowledgeFileTree.tsx`。按任务持久化恢复状态、接入宿主续接和状态事件。

验收：回合完成但有 pending 项或全部 partial 时明确显示未完成；关闭弹窗不中断任务；切换项目不串进度；暂停拒绝迟到写入；重启仅提示继续；重复点击不重复调用；预算跨自动续接累计；源/目标变化时只重试受影响项；重复读取和无变化提交不触发续接。用户原话证据覆盖首次提交、自动续接、用户点击继续及原消息变化四类场景，自动生成的续接文本不得作为事实证据。

### 第三阶段：覆盖详情与真实质量验证

补大纲详情、来源覆盖和按引用更新的可读反馈。使用脱敏的“续命”固定快照、少量/空材料样本、长文分页和外部编辑场景，保持模型及输入一致做对照；每个真实样本限两次，报告全部结果，不只展示成功案例。

### 什么内容值得保存

先回答“未来哪类问题会使用这条知识、用错或漏掉会怎样”。重要性用于安排读取与提炼顺序，不能提高不可靠内容的可信度；不使用未经校准的 80 分总分抵消事实错误。

| 优先级 | 判断依据 | 处理方式 |
| --- | --- | --- |
| 高 | 影响核心用户任务、付费权益、数据处理承诺、发布决策或重大重复错误；即使只发生一次也值得记录 | 优先核对关键依据、适用范围和例外；未解决缺口必须显式保留 |
| 中 | 反复使用的流程、已确定的术语与规则、具有决策价值的取舍和验证记录 | 按明确主题保存，指向主要维护文档 |
| 低 | 一次性执行流水、临时路径、重复截图说明、没有项目增量的泛泛建议 | 保留必要来源定位或合并，不单独生成知识正文 |

业务筛查关注目标用户与核心任务、业务对象与状态、规则和例外、权益与商业边界、数据生命周期、交付验收以及关键决策原因。只对当前项目和文档类型适用的维度提出要求，不强制所有项目填同一套字段。已确认来源范围覆盖不到的维度标为“未评估”，不能写成“不存在”或擅自扫描扩大范围。

### 按内容类型判断最低充分性

| 内容类型 | 达标的最低信息 | 不能混淆的界限 |
| --- | --- | --- |
| 项目事实/当前能力 | 明确对象、结论、适用版本或截至时间、能直接支持该结论的依据 | 代码存在不等于功能已发布，报告声称核验不等于本次独立核验 |
| 业务规则/权益 | 适用角色与对象、触发条件、规则及结果、会改变结果的例外与边界 | 收费、会员、隐私口径的冲突未解时，不能任选一版作当前规则 |
| 业务流程 | 输入或前置条件、关键步骤与状态变化、输出或验收条件、重要失败路径 | 操作步骤清单不能替代完整业务行为，已知失败路径不得省略 |
| 决策 | 具体问题、选择与原因、主要取舍、决定状态和可验证出处 | Agent 建议、会议讨论、用户采纳是不同状态；无采纳证据不能写“已决定” |
| 计划/假设 | 提出者或来源、目标、尚未证实部分、验证方式与判据 | 可作为计划入库，但不能把目标阈值写成真实结果、把假设写成已证实需求 |
| 历史记录/实验 | 时间、版本、设备/环境、观察结果与证据限制 | 模拟器、本地 StoreKit、单次 QA 不能推出真机、生产支付或发布审核通过 |

关键业务断言必须能对应到具体引文或有效用户事实证据，保留其限定条件；不能拿一段真实引文为整篇不相关结论背书。用户声明可支持“用户要求/用户提供的事实”，不能自动变成外部市场或运行数据的独立证明。没有来源的连接性说明可以是解释，但不得夹带新的业务事实。

### 三种准入结果

| 结果 | 条件 | 保存与调用行为 |
| --- | --- | --- |
| 可入库（按类型使用） | 有明确复用价值；关键断言有相应证据；适用边界明确；没有未披露的重要冲突或遗漏；内容可独立理解 | 保存正式主题文档并按事实、规则、计划或历史类型检索。语义评估通过不自动写成 confirmed |
| 待补证据 | 有价值，但重要断言缺依据、适用版本不明、关键流程缺口或当前规则冲突未解 | 保存可读草稿与具体缺口，默认事实上下文不引用；用户显式查询待核内容时携带原因与类型返回 |
| 不新增知识 | 重复、无可复用增量，或应归属其他位置 | 说明合并对象或保留原材料；临时进度留会话、协作偏好走独立记忆、可执行步骤按既有 Skill 路由；不自动删除原件 |

一篇资料允许拆分处置：可信的稳定内容保存，冲突规则列入待核；有完整证据的“两个历史版本曾给出不同说法”本身可以作为冲突记录入库，但不能据此输出当前业务答案。少量有充分边界的信息也可达标，字数、章节数和资料数量均不是准入门槛。

生成进度、准入结果、事实是否经用户确认保持独立；不恢复逐篇人工批准。仅在确需用户解决业务歧义时，给出具体冲突及其影响。用户确认整理范围或继续生成都不等于确认内容事实。

### 最小评估机制与影响

1. 提炼前为当前项列出少量必须回答的业务问题和高优先级规则；依据已读来源形成关键结论到证据的对应，不为每句套复杂表格。重要来源尚未读取时，覆盖状态为未知。
2. 生成后检查这些问题是否被回答、重要否定条件/例外是否被保留、结论是否超出证据，并给出上述准入结果及具体原因。程序负责引用与结构校验，Agent 负责语义检查；同一模型自查不是独立事实证明。
3. 在已有文档版本旁保存紧凑评估记录：正文哈希、来源版本、评估规则版本、内容类型、适用范围、准入结论、重要断言的证据映射及未解决问题。只保留可审阅的结论，不保存模型隐藏推理。旧引用/旧评估不得套用到新正文。
4. 正文或来源变化时只复核受影响内容；旧合格版本可以保留历史，但已失效来源支持的当前结论也必须暂停自动使用，不能继续借旧评估当作现状。旧文档缺评估时可读且标“未评估”，不自动标达标；默认事实注入保守处理，显式检索可带该状态返回。
5. 最小准入策略需要同时接入搜索、自动上下文、读页/引文返回和 UI。第一阶段必须覆盖这些通路，避免只在 UI 提示后模型仍无条件使用草稿；计划与历史在匹配查询时可以返回，但类型、日期和证据限制不可丢失。

复用既有读取、提交事务和当前会话，不新增常驻评审服务；语义检查与必要补读计入同一任务的时间、轮次和上下文预算，额度不足时保留待补草稿。额外开销来自有限的证据映射与内容检查，尚无实测费用或速度结论。该变化会收紧未评估旧文档的自动使用范围，UI 应解释原因并提供按需评估入口，不能以迁移兼容为由把旧数据批量标成通过。

### 内容验收

采用明确的关键断言与业务问题清单评估固定样本，不用生成器自己给的总分作唯一依据。有限样本中的目标是：预先标定的重要规则与例外均有去向、每个关键断言能追溯支持证据、计划和历史不被误作当前事实、冲突内容不进入无提示的默认事实上下文。达不到就报告具体遗漏或误用；样本通过不能推广为全库无误。

至少覆盖：有效引用却不支持正文结论；付费权益互相冲突；隐私口径发生变化；计划阈值误作实测；模拟器验收误作生产上线；有效的短规则；部分可信部分待核；重复内容合并；正文/来源修改后旧评估失效；跨新会话读取仍保留类型与限制。程序的引用、版本与准入结构校验已有离线回归；上述语义质量不能仅靠程序证明，真实模型评估仍需在明确模型和预算后单独执行。

## 评审边界

本方案不改变用户确认范围才开始建库的约定；补来源不得借机扩展主题或目录权限。恢复不会自动选择“最新”内容覆盖用户编辑，也不会取消证据核验。实现已复用当前会话、写租约、原子清单和 deferred queue；开销收益仍需由固定样本和真实任务测量。Nowledge Mem 定向检索已尝试，本机服务连接拒绝；历史约束依据当前会话和仓库记录核对。
