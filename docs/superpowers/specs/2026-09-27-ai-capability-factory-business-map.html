贯穿四个环节的主键：版本

四个环节必须能被同一个身份串起来：场景 ID + 版本号。定义产出 v5；运行记录挂在 v5 上； 评测分数属于 (v5, 数据集版本)；交付出去的能力包也是 v5。
当前缺口：版本只出现在「场景定义」页。运行记录只有 run id、评测只有分数、导出没有版本号 —— 于是"改了提示词之后，之前那些运行记录是哪一版的"答不上来。这是结构问题，不是 UI 问题。

界面地图：当前 vs 应有

环节当前界面应有界面差在哪
定义 「场景定义」tab 同左 + 版本列表/回滚 Agent 会反复改，没有回滚用户不敢让它放手改
运行 「运行」tab（含提交历史） 同左 + 取消 / 批量 / 只重跑失败步 300 章的小说现在要提交 300 次
评测 运行页右栏的「指标/对比」两页 独立一级 tab：数据集 + 评测历史 + 版本对比 + 逐条判据结果 核心动作藏在别人的右栏里；无数据集、无历史
交付 顶栏一个「导出」按钮 独立一级 tab：导出历史 + 包版本对应 + 关联项目接入状态 只出不进：不知道谁在用、用的哪版、有没有改坏

缺口清单

P0不做就用不起来

  • 01数据集无入口没有数据集，评测只能跑上一次的输入，和"再提交一次"没区别
  • 02失败案例回灌缺失迭代闭环 = 失败→固化成用例→改→重跑。缺了它评测集永远是初始那几条
  • 03版本历史与回滚没有回滚，用户就不敢让 Agent 放手改
  • 04空态与新建流程新项目打开是空的、新建场景之后是什么，整段没设计

P1用起来会疼

  • 05批量提交与排队一本小说 300 章；连续提交 10 个任务的排队状态也没有
  • 06只重跑失败步骤文案里承诺过，界面上没有这个动作
  • 07评测历史与版本对比要证明 v4 比 v3 好，需要两次评测都在
  • 08逐条判据的通过情况现在只有聚合分数，看不到"第 3 条判据有 4 个用例没过"
  • 09取消 / 中断运行历史里有"已中断"，却没有取消按钮
  • 10成本可见评测是烧钱的，状态条只有"预算内"三个字
  • 11虚拟接入 → 真实接入现在只有"桩 / 4 比 4 一致"，没有"该项目已接真接口"
  • 12包版本与场景版本对应导出后场景继续改，包还是旧的，两者关系没表达

建议的界面结构

tab承担什么
运行提交任务 · 本次流程与输出 · 提交历史作为它的子视图
评测数据集管理 · 运行评测 · 评测历史 · 版本对比 · 逐条判据结果
场景定义步骤与提示词 · 契约与评审 · 版本列表与回滚
交付导出能力包 · 导出历史 · 包与版本对应 · 关联项目接入状态

为什么把「提交历史」并进「运行」而不是继续当一级 tab：面板最窄只有 300px，四个 tab 各约 75px 是下限； 五个 tab 会挤到 60px 以下，中文标签放不下。而「历史」与「运行」本来就是同一次活动的两种视图。

这份地图只回答"界面该有哪些板块"。每个板块内部的交互（比如数据集怎么建、用例怎么从失败运行里长出来） 等这张结构确认后再逐个展开。
