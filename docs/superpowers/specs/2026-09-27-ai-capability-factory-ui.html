交互设计说明
01
对话为主，图为辅
中栏最宽，是唯一的主工作区；工作流步骤以紧凑列表嵌在对话消息里，不做独立画布。这与 Canvas 正好相反——那里是人在拖拽作图，这里是人跟 Agent 说话。步骤详情全部收在右栏，不和对话抢位置。
02
「采纳」与「冻结」是两个显式动作
Agent 只能产出草案和提案，都不能直接生效。采纳把草案变成当前版本，冻结把指标钉死。两个按钮都在卡片底部、都需人点，因为它们分别决定「用哪套提示词」和「用什么标准衡量」。
03
约束与指标分列
「约束合规率」永远和准确率类指标并排出现，且不合法样本不计入后者。指标页显式标注「有效样本 11/12」——合法样本太少时这里会变成拒绝给结论，而不是给一个漂亮分数。
04
每一步都可展开
轨迹里点任意步骤展开看输入、渲染后的完整提示词、约束校验结果。这是「编排」相对「单条提示词」的唯一增量：失败常常发生在中间步骤，只看最终回答定位不到。
05
虚拟接入标注契约来源
桩卡片显式写明「契约来源 src/api/account.ts」和一致性检查结果（4/4 字段一致）。没有这个标注，用户无法判断桩是照真实接口生成的、还是随便造的假数据——后者会导致工厂里全绿、真实接入全部返工。
06
导出是人工动作，状态条常驻提醒
导出入口在顶栏，底部状态条常驻「导出为人工动作 · Agent 不可自主发布」。因为导出会改变另一个项目的行为，且提示词改动在代码 review 里看不见，这个边界必须在界面上持续可见，而不是藏进设置。
07
对比页在指标未冻结时拒绝给结论
对比页直接说明两次运行的前提（同一指标、同一模型、同一数据集），并写明「若指标未冻结，本页拒绝给出结论」。宁可空着，也不给一个不可归因的差异。
08
与实现的分期差异
本稿演示的是完整目标交互。tool 步骤与「虚拟接入」属于第二阶段；第一阶段的端到端闭环只有 llm 与 extract 两种步骤。稿子里保留它们，是为了让接入形态在动手前就被看清楚。
