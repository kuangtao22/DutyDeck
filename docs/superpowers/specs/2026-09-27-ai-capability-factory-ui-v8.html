交互设计说明 v8
面板不承载 Agent 入口
01
产品模型：面板 + Agent 才是一个完整产品（本轮纠正）
v7 我在场景定义页里放了一张「让 Agent 设计流程」的卡：一个输入框 + 一个生成按钮。这是自相矛盾——前面才把对话从面板里删掉，这等于又把对话藏回面板，而且藏得更难发现（一个只有一句话输入框的伪对话）。
正确的模型是：面板是仪表盘与操作台，Agent 是唯一的设计与对话入口。所以面板里不能有任何「发起 Agent 生成」的入口——没有设计期的输入框，也没有「让 Agent 重写这一步」这类隐含命令的按钮。
面板能做的是两件事：取景（显示场景现在什么样、这次跑出了什么）和搬运（把某次运行、某一步作为引用带到会话）。改流程的动作发生在会话里，结果以草案回到面板等采纳。
02
「写死」是两层东西，必须分开
第一层是缺陷，我认：v6 的编辑器只是「一个填好的例子」——步骤固定 4 个、不能增删换序、每步形态照账号查询写死，而且数据流被藏起来了（每步只能吃上一步输出）。
第二层是必要约束，不能放开：步骤类型只有 llm / extract / tool，评测器类型只有 extraction / tool-trace。放成「任意结构」后，参考 runner 无法执行、评测器无法给分、跨版本比较不成立，模块会退回成绘图工具。
正确做法是类型收敛、组合自由：任意缝隙插入、删除、上移下移、改标题、切换类型（只换「能配什么」，公共字段保留）、每步声明输入来源（workflow.text / 上一步输出 / 常量）。
03
场景的结构：六个概念，前三个是定义、后三个是事实
定义（可编辑、有版本）——① 场景：名称/描述/输入输出契约，这是交付给别的项目的那个东西；② 步骤：执行单元，类型决定它能配什么（llm→提示词；extract→提示词+输出约束；tool→能力绑定）；③ 数据流：每一步的输入从哪来，显式声明，不靠隐式上下文。
事实（只读、不可改）——④ 能力声明：对外部世界的需求，由接入方绑定实现；⑤ 运行：一次执行，带完整轨迹；⑥ 评测：在一批输入上的质量结论，指标冻结。
04
项目与场景是两件事：面板只认当前项目
面板绑在 DutyDeck 当前项目上，左栏只列本项目的场景，不再混排其它项目；窄栏时的场景下拉也只列本项目。切换项目用 DutyDeck 自己的左侧栏，每个项目的场景互相独立。项目名保留在场景条的面包屑里（账号查询箱 ▸ 账号状态查询），但它只是上下文标签，不是选择器。
05
融合通道一：共享同一份事实
场景定义、版本、运行记录都存工作区里，面板和 Agent 读写同一份，没有第二套真相。Agent 改了提示词 → 场景出新版本 → 面板顶部出现提示条「草案 v5 · Agent 改了第 2 步的抽取规则」，带「查看差异 / 采纳 v5」。注意：Agent 的改动默认是草案，不会自动生效。
06
融合通道二：面板 → 会话只传结构化引用
「把这次运行带到会话」「把这条输出带到会话」、以及失败步骤旁的 ↗，这三个动作都只搬运、不发命令：把 {项目, 场景, 版本, 运行, 步骤} 作为引用连同有界摘要带进当前会话，你不需要复述「第 4 步少了 expiresAt 那个字段」。
刻意不写「让 Agent 分析这次运行」——面板无法保证会话真的会去做某件事，许愿式的按钮是不诚实的 UI。带过去之后说什么，由你在会话里决定。
摘要有界（不塞整份轨迹），避免上下文膨胀与二次成本。
07
融合通道三：会话 → 面板只做定位
Agent 改完场景后，它的工具回执里带一行「工厂已更新 · 查看」的可点击入口，点击聚焦本面板并定位到该场景。这是 Agent → 面板的唯一通道：它不改动面板内容，只做定位，避免两处都能编辑。
08
面板不承载对话，这条边界要守住
头部有一枚「已绑定会话 a1f3」的标记（点它切回主会话），但面板里没有输入框、没有消息流。要跟 Agent 说话就去主会话，要提交与观察就留在这里。理由：同一个项目里两处都能对话，会立刻产生「刚才那句话是在哪儿说的」。
09
权限边界：Agent 能做什么、不能做什么
Agent 可以：建草稿、改提示词出新版本、读运行记录与轨迹。人来做：采纳版本（面板上的「采纳 v5」）、导出能力包、提交任务。理由：采纳决定之后用哪套提示词，导出会改变另一个项目的行为，两者都不适合让 Agent 自主生效。
10
观察台内部还有一层自适应
观察台自己是第二个容器：宽度不足 560px 时，步骤行的「类型 + 耗时」折到标题下面一行，指标从四列变两列，提交历史隐藏指标列。判据看观察台宽度而不是面板宽度——双列模式下观察台只有 300 多像素。
11
断点与宽度
<600px 单列（场景进头部下拉、观察/详情分段切换）、600–1039px 双列、≥1040px 三列。605px 是 1512 屏展开工作区的默认宽度，最常用。底部宽度条可直接切 300 / 360 / 480 / 605 / 720 / 880 / 1120 试。
12
Agent 建流仍然主张，但入口在会话里
「流程由 Agent 设计」这个主张不变——从零手搭一条四步流程要写四段提示词、定义三组约束，而 Agent 读一遍项目就能给出可跑的草案，人再改。但这个动作发生在会话里，不在面板里：你在会话里说要做什么，Agent 产出草案，面板顶部出现「草案 v5 · Agent 改了第 2 步的抽取规则」，你在这里采纳或继续改。
面板为此只提供两样东西：联动状态（这个场景的来源、当前是 v4 生效还是 v5 待采纳）和一个定位入口「在会话中打开此场景」。
这一步能成立的前提是 Agent 读得到项目（接口定义、数据模型、技术栈），否则它只能凭描述猜，产出的字段对不上真实项目。
