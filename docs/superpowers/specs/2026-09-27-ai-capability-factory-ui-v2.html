交互设计说明 v2
本轮按反馈改动的地方
01
视觉改用项目现有 token
颜色、圆角、阴影、字体全部取自 globals.css 的 :root 与 .dark：6px 圆角基准、hairline 边框、Inter + tabular-nums、shadcn 语义色。右上角可以切深浅色，两侧都是项目里已有的取值。按钮的立体片状阴影也照抄了 ui/button.tsx。
02
场景挂在项目下面
左栏是「项目 → 场景」两级，和左边栏「工作区 → 会话」的结构一致；一个项目可以有多个场景，项目标题可折叠。切换项目时只换场景列表，不切走整个面板。
03
去掉对话，改成「提交任务」
提交入口在顶栏和场景条两处，点了弹对话框：粘正文 → 开始运行 → 工作流自动跑。中栏是观察台，不是聊天记录。这样一次提交就是一件事，可以反复跑同一个场景而不用重复描述需求。
04
「提交」与「评测」分开
提交一次 = 跑一个输入，看过程与这一条的输出；评测 = 跑一整套用例，产出一组指标。两者目的不同，所以分两个入口、两块结果。你可能连续提交十几次都不需要跑评测。
05
观察面就是「运行过程 + 本次输出」
中栏按顺序是：本次提交的输入 → 运行过程（每步的编号、类型、耗时、约束校验结论）→ 本次输出 → 评测结果 → 提交历史。点任意步骤跳到右栏看它的输入、渲染后的完整提示词和校验明细。
06
场景定义收在右栏，迭代出口留给 Agent
既然这个面板不再对话，场景的提示词、约束、指标就放在右栏「场景」页只读展示；要改，走「在 Agent 中迭代此场景」到 Agent 会话里改，改动生成新版本、不覆盖当前版本。这样「看」和「改」分开，改的入口只有一个。
07
约束与指标仍然分列
本次输出按 strict 规则判为 invalid（缺 expiresAt），因此不计入评测指标，但任务本身照样可读可用。指标卡显式标注「有效样本 11/12」。
08
与实现分期的差异
tool 步骤与「虚拟接入」属于第二阶段；第一阶段端到端闭环只有 llm 与 extract，先用小说角色提取跑通。稿子里保留它们是为了让接入形态在动手前被看清楚。
