# DutyDeck 内置本地模型实施验证记录

日期：2026-10-13

## 结论

DutyDeck 内置本地模型的代码链路已完成：用户可在“设置 → 关于/更新 → 可选环境能力”按需下载并校验一次受管 `llama.cpp` 环境，随后在模型配置的供应商详情页下载和管理 GGUF 模型；模型资产下载与校验、受管 `llama-server` 生命周期、能力验证、窄 IPC、渠道投影、Pi 注册和设置页交互均已接入。Ollama 仍是独立外部供应商，不能被当作内置运行时依赖。

本轮验证没有下载真实 GGUF 权重，也没有在真实 `llama-server` 上完成推理。测试中的服务端是受控 fake server，因此验证的是状态、边界和协议行为，不是模型质量、吞吐、显存占用或硬件兼容性。

## 按需安装流程

- DutyDeck 不再在默认构建或首次启动时隐式下载 llama.cpp。
- 关于/更新页的“可选环境能力”先展示固定版本、平台、架构、归档大小和安装状态；用户点击“安装运行环境”后，主进程执行下载、校验、原子安装，并支持取消和重试。模型供应商详情页只展示引擎状态和跳转入口，避免重复安装操作。
- 环境未进入 `installed` 前，DutyDeck 模型目录、模型下载、加载和启用按钮均保持锁定；环境完成后多个 Qwen/Gemma GGUF 模型共享同一引擎。
- 引擎失败不会静默回退到云端或 Ollama；Ollama 的环境和模型仍由 Ollama 自己管理。

## 完整安装包边界

当前仓库只提交了引擎版本清单与四个平台的 SHA-256，未提交二进制；默认构建不会替用户下载真实引擎。用户主动安装时，主进程才访问固定的 GitHub Release 归档并写入 `~/.DutyDeck/engines/llama.cpp/...`。完整安装包和联网下载流程仍需在可联网构建机及目标平台验证。

待可联网构建机完成以下验证后，才能关闭该边界：下载并校验四个平台引擎、生成资源 manifest、执行 electron-builder，并在目标平台启动一次真实 `llama-server` 完成健康检查和能力探测。

## 设计约束

- 默认模型目录是活动数据根下的 `models/`，默认路径为 `~/.DutyDeck/models`。
- renderer 只能看到脱敏快照；回环地址、临时 token、引擎路径和启动参数留在主进程。
- 能力测试不会自动启用模型；停止模型不会静默切换到云端渠道。
- 没有真实权重或引擎资源时，运行时会 fail closed，UI 必须展示不可用原因。
